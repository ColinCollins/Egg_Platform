# 购买入口断网前置校验

## 2026-09-14 需求与原行为

- iOS 26 无网时点击购买，可能先开启购买中的界面锁和不自动超时的 WaitingPopup；如果平台购买界面未拉起且没有结果回调，关闭 WaitingPopup 后，ChestGift 的 ClickBlock、商店及 NoAd 入口的按钮锁不会自行复位。
- `ShopItem` 仅向 `ShopPanel.TryToPurchase()` 转发点击；旧版 Shop 与 ChestGift 都没有点击前断网校验。Shop 偶尔出现的网络提示来自失败结果回调中的 `PurchaseManager.OnPurchaseFailed()`，不能保证无结果回调的路径显示提示。

## 本次行为与影响范围

- `ShopPanel.TryToPurchase`、`ChestGiftPopup.OnPurchaseClick`、`CoinGiftPopup.OnPurchaseClick`、`NoAdsPopup.BuyNoAd`、主线/Draw/IWanner 三种胜利面板的 `NoAdBtn`，以及 `ShopPanel_SkinPart.OnPurchaseButtonClicked`：在设置购买中状态、禁用按钮、开启 ClickBlock、发送 IAP 点击打点及调用 `PurchaseManager.Purchase()` 之前，检查 `Application.internetReachability`。
- 已报告无网络时直接调用既有 `PurchaseManager.OnPurchaseFailed()` 显示 `U_NoNetWork_Tips_01`，当前点击结束，不创建 WaitingPopup，也不进入本次购买的 UI 锁状态。其它状态沿用原点击、SDK、回调、发奖、存档和打点流程。
- 冷启动离线且商品元数据未加载时，ChestGift 原按钮门禁会使点击事件无法发生。后续真机反馈表明，设备报告网络可达但商品详情或价格未就绪时仍会发生同类无反馈；现将按钮可交互条件改为本地 Offer 有效且 PurchaseManager 存在，商品详情仅控制价格展示，不再控制点击。商店入口仍在加锁前确认 PurchaseManager 存在，避免无请求的面板锁。
- 本次没有修改 `PurchaseManager`、Guru SDK、`WaitingPopup`、控制器购买结果处理、Prefab、配置、存档结构或平台分支。`ShopItem` 本身继续只转发点击，前置校验放在拥有业务锁的 `ShopPanel`。

## 入口与结果链复核

| 入口 | 已报告无网时 | 联网请求与成功结果 |
| --- | --- | --- |
| ShopItem / ShopPanel | 网络提示；不锁商店 | 原 Shop→Product 映射；`OnPurchaseSuccess()` 与 Shop 金币补发 |
| ChestGift | 有效 Offer 可点击显示网络提示；不启用 ClickBlock | 本地 Offer 有效即可进入前置检查；详情缺失由公共购买失败回调提示，正常成功时控制器记录购买并交付礼包奖励 |
| CoinGift | 网络提示；不设置控制器忙碌状态 | 原控制器购买回调交付金币，视图只播放动画 |
| NoAdsPopup、主线/Draw/IWanner NoAdBtn | 网络提示；不锁关闭或导航 | 原 `OnPurchaseSuccess()` 交付 NoAds 权益 |
| 商店皮肤内购 | 网络提示；不锁皮肤按钮 | 原皮肤购买回调交付皮肤 |

## 验证、未验证项与回滚

- 已静态核对八个入口的断网分支均位于各自 UI 锁、`IAP_CLK` 和 `Purchase()` 调用之前，联网分支仍调用原 `PurchaseManager.Purchase()` 与原结果回调；`U_NoNetWork_Tips_01` 在当前 `Assets/Resources/I2Languages.asset` 中具有非空简中、英文等文本。八份改动脚本的 Roslyn 语法解析、目标文件 `git diff --check` 均通过。使用 Unity 当前 `Assembly-CSharp.rsp` 和 Unity 自带 Roslyn 编译整个运行时程序集，结果为 0 个编译错误、113 个警告；未建立 warning 变更前基线，不将其归因于本次修改。
- `Application.internetReachability` 只表示设备当前连接类型；仍显示 Wi-Fi/蜂窝但无法访问商店、点击后才断网、等待弹窗被手动关闭且 SDK 不回调的情形，本次前置校验不能判定平台是否已开始交易，状态为 `uncertain`，需要 iOS 真机日志确认。不能仅凭关闭 WaitingPopup 将潜在平台交易当作失败并丢弃后续结果。
- 复核另见既有皮肤页生命周期风险：`ShopPanel_SkinPart.OnDisable()` 会清空 `_pendingPurchaseSkin`，`ShopPanel.IsAnyActionInProgress()` 不读取皮肤购买状态；若等待弹窗被关闭后切页或关商店，晚到的成功回调可能因待购 Skin 丢失而无法交付。此项不是前置断网分支造成的；用户决定本次不处理，留待单独复现和评估，不应把代码编译通过解释成这一情形已安全。
- Unity PlayMode、iOS 26 离线/切网、Android 横屏及真实商店弹窗尚未验证。独立 `dotnet build` 因 `Temp/bin/Debug` 缺少 Unity/Guru/Bear 依赖 DLL 失败；Unity 自带 Roslyn 的完整运行时程序集编译已提供代码级结论，不能替代真机支付验证。
- 回滚时移除八处点击前断网分支、ChestGift 的离线按钮例外及商店 Manager 缺失检查；原购买和 SDK 代码无需回滚。
