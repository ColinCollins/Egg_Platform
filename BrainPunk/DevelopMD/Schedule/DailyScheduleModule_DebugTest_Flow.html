Current Implementation

DailyScheduleModule 调试流程

当前 GM 调试入口已经收敛为 2 个按钮：Prepare CrossDay + Check 和 Refresh Daily Data。第一个按钮会先准备跨天，再立刻执行一次 `ScheduleSystem.CheckAllModules()`；第二个按钮保留为独立复查入口。

当前定位

这套调试工具用于验证 `DailyScheduleModule` 的跨天判定、`GameSchedule` 的落库结果，以及关键 daily count 的当前值。

  • 不改系统时间
  • 不新增 fake refreshable
  • 只改 `DB.GameSchedule["Daily"]`
  • 只调 `ScheduleSystem.CheckAllModules()`
  • 展示 `DailyCount.InterstitialNoAdPopup`
  • 展示 `DailyCount.ShopFreeCoin`
  • 不提供 Restore

Step 0: 先看当前状态

打开 GM 面板后，`GMDailyScheduleTestController` 会持续刷新调试文本，先不要点按钮，先确认当前存档状态。

文本字段

  • Now UTC
  • Today UTC Start
  • Daily Last Refresh
  • Daily Last Refresh (Local)

DailyCount 字段

  • DailyCount.InterstitialNoAdPopup
  • DailyCount.ShopFreeCoin

判定字段

  • Prediction
  • Prepared CrossDay
  • Module Registered
  • Last Action

Step 1: 点 Prepare CrossDay + Check

这个按钮是当前推荐主入口，它已经包含“准备跨天”和“立即检查”两段动作。

按钮动作

  • 将 `DB.GameSchedule["Daily"]` 写成昨天 UTC 0 点
  • 调用 `DB.SaveGameSchedule()`
  • 立即调用 `ScheduleSystem.CheckAllModules()`

预期变化

  • `Daily Last Refresh` 推进到今天 UTC 0 点
  • `Prediction` 变成 Should Skip
  • `Last Action` 记录 before / after 时间

同时可观察

  • 两个 `DailyCount` 当前值
  • 哪些计数没有被清零
  • 是否存在模块未注册问题

Step 2: 点 Refresh Daily Data 复查

如果需要确认“同一天再次检查不会重复触发”，再点一次独立复查按钮。

按钮动作

  • 确保 `DailyScheduleModule` 已注册
  • 直接调用 `ScheduleSystem.CheckAllModules()`

预期变化

  • `Daily Last Refresh` 不应继续变化
  • `Prediction` 保持 Should Skip

说明

如果 `Daily` 时间戳已经推进，但某个业务 count 没变化，优先怀疑对应模块没有在这次检查时注册到 `DailyScheduleModule`。
