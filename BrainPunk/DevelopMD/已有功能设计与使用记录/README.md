# 已有功能设计与使用记录：日期归档

从 2026-09-17 起，新增通用设计事实与使用记录按日期写入本目录，以减少长期集中修改一个文件造成的冲突。

## 写入规则

- 文件名统一为 `YYYY-MM-DD.md`，采用任务记录时的本地日期（Asia/Shanghai），例如 `2026-09-17.md`。
- 同一天只维护一个日期文件：不存在时创建；已存在时更新对应主题章节，新主题新增章节，保留其它任务内容。
- 不按任务名称、时间戳或序号另建同日副本；跨日的新进展写入新日期文件，可链接此前记录。
- [原记录](../已有功能设计与使用记录.md) 保持原样，只读查阅，不追加、改写、迁移、拆分历史内容或重新格式化。
- 模块与关卡专属功能、结构、风险文档继续在原归属目录维护；本目录记录通用事实、验证摘要和相关文档链接，不替代权威模块文档。
- 写入前读取当天文件最新内容，仅修改本任务章节，不覆盖其它任务的记录。日期拆分不能保证同一天并行编辑完全无冲突。
- 本说明不维护逐日索引；直接按文件名查看日期，避免每次新增记录又集中修改索引文件。

## 查阅方式

检索既有功能时，同时搜索旧历史文件和本目录。在 BrainPunk 目录运行：

```powershell
rg -n "模块或类名" DevelopMD/已有功能设计与使用记录.md DevelopMD/已有功能设计与使用记录
```

## 日期文件写法

文件标题为 `# YYYY-MM-DD 已有功能设计与使用记录`，每个任务使用独立的二级主题标题。
主题内简要记录需求与原有行为、影响文件、变更与使用边界、可复查证据、验证结果、未验证风险及回滚方式；仅查阅分析时明确未修改运行行为。
