## 1. OneLink 关卡直达与 GM 测试

### 当前职责与入口

- `GameSDKService.Initialize()` 创建并初始化 `OneLinkManager`，`GameAnalytics` 在 AppsFlyer prepare 后把 AppsFlyer 回调接入同一管理器。
- Unity `Application.deepLinkActivated`、AppsFlyer deep link、编辑器/`DEBUG_MODE` 测试 API 最终写入单个 pending 请求。
- `LoadManager` 在首页弹窗分发完成后置位启动门禁；`StartPanel.LateUpdate()` 在主场景、应用有焦点、主控制器处于 `START` 且没有阻塞 Popup/Top/closing/shared-mask 时尝试消费 pending。
- `OneLinkLevelRouter` 按 `GameType + Path` 路由主线、DrawGame、IWanner。Path 比较不区分大小写。

### 数据、资源和状态链

- 主线：解析路径 → 校验关卡存在/解锁 → 记录目标 → 进入主线。
- DrawGame：检查远端玩法开关、控制器 ready 和存档 → 必要时写入 `PassedLevels` → 打开/获取选关 UI → 进入 Draw 关卡；失败时尝试回首页。
- IWanner：校验组和关卡 → 修复旧档集合 → 必要时把组 ID 写入 `UnlockGroups` 并 `SaveIWannerGame()` → 进入组/关卡。
- UI 阻塞判断包含 Popup/Top 栈、closing view 和共享遮罩，避免系统弹窗尚未结束时切关。

### 当前失败边界

- `OneLinkManager` 在调用路由前把 `_pending` 清空；同步路由返回失败或抛异常时只记录日志，没有自动回队证据。
- Draw/IWanner 路由在真正资源进入前可能已经写入解锁/通过状态；后续 UI 或资源失败可能形成“状态已变、关卡未进入”。
- Android manifest 当前只声明 `https://brain.gurugame.ai/default_link`；代码同时识别 `brainpunk.onelink.me`。实际签名包、域名映射、assetlinks/AASA 和 AppsFlyer 后台闭环没有本轮实测证据。
- `ProjectSettings.asset` 的 Android 与 iPhone define 都包含 `DEBUG_MODE`；`StartPanel` 会创建 `GMPanel`，OneLink GM 入口和测试 API会被编入。测试路由复用正常解锁与存档，发布构建是否另有脚本移除该符号为 `uncertain`。

### 本轮验证基线

- 当前源码 OneLink Editor stub Harness：92 项通过。
- 当前源码 Android `DEBUG_MODE` stub Harness：151 项通过。
- 相关三个 Prefab 静态检查未发现重复 fileID、本地引用缺失或脚本 GUID 缺失。

## 2. DrawGame 远端关卡顺序

### 当前职责与入口

- `DrawGameLevelCtrl` 从 Luban 表建立本地顺序，并读取 `drawgame_config` 远端 JSON。
- 冷启动和运行期更新共用 `TryPrepareRemoteConfig()` 验证：支持字符串/整数 ID，拒绝空列表、重复、未知数据和缺 Prefab，成功后补 `DLevel_999` 并应用。
- `LoadManager` 的远端配置完成边界在 DrawGame 初始化之前；运行期通过远端配置变化再准备并应用候选顺序。

### 状态与消费者链

- JSON → 候选 ID → Luban 数据/Prefab 闭包 → `_levelSorts`/generation → Draw 选关、胜利下一关、OneLink Draw 路由、批量解锁。
- 保存或配置失败时应保留本地/上一份有效顺序；真正运行期行为仍依赖 Firebase 时序与资源包内容。
