## 3. Dig 首页入口、Controller 与存档基线

### 入口与资源

- `StartPanel.prefab` 当前包含两个源 GUID 为 `705853c3f86b8f2449a93006848d3f62` 的 DigGameEnter 实例；两个实例都没有失活 override，源 Prefab 根节点默认激活。

- `tbdiglevelsort.json` 将排序 1 映射到配置 40001，`tbdigleveldata.json` 再映射到资源 `DigLevel_001`。

### UI、状态、资源与存档链

玩家点击任一 Dig 入口
→ `DigGameEnter.Enter`
→ `GameManager.TryEnterDig`
→ `PlayControllerManager.TryEnter(Dig)`
→ `DigPlayCtrl.TryEnterCurrentLevel`
→ 创建 `EnterLevelLoading`
→ 遮满后经 ResourceManager 加载 `DigLevel_001.prefab`
→ `DigLevelCtrl.InitializeRuntime`
→ 创建独立 HUD
→ 写入 `DB.DigGame.CurrentLevel` 并保存
→ 揭幕后开放输入。

第一次点击会把 `_transitioning` 置为 true。转场完成前点击另一入口时，ControllerManager 因 Dig 已是活动控制器直接返回成功；随后 `TryEnterCurrentLevel()` 因 `_transitioning` 拒绝，`GameManager.TryEnterDig()` 再调用 `ReturnToStartPanel()`。该状态链是源码直接结论，但尚无 PlayMode 玩家画面证据。

### 回滚边界

- 若双入口不是产品要求，最小回滚是恢复单一 DigGameEnter 实例及唯一 Inspector 绑定，不修改共享 StartPanel 脚本或 Dig Controller。
- 若必须保留双入口，应以两个入口共享的进关门禁为目标，并覆盖转场、失败回退、关闭重开与存档不变性；当前报告不实施该行为变更。

- `Twinkly SDF.asset`：缓存 glyph/character 从 1/1 变为 0/0，内嵌 atlas 从 1024×1024 缩为 1×1。

- 两份 FontAsset 都保持 `m_AtlasPopulationMode: 1` 与 `m_ClearDynamicDataOnBuild: 1`；对应 TTF 存在且 `includeFontData: 1`。
- 当前 `Assets/Game` GUID 直接匹配：Twinkly 30 个文件，en 181 个文件。该计数用于描述静态影响面，不等同于运行时同时加载数量。
