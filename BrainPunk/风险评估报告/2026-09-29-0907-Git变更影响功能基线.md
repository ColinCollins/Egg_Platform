## 3. TMP 动态字体资源基线

### 资源职责与引用

- `Twinkly SDF.asset` 当前为动态 atlas 模式（`m_AtlasPopulationMode: 1`），源字体 GUID 指向现存 `Assets/Game/ArtSrc/Font/Twinkly.ttf`，并把 `en SDF` 列为 fallback。
- `en SDF.asset` 同为动态 atlas 模式，源字体 GUID 指向现存 `Assets/Game/ArtSrc/Font/en.ttf`；它同时被 `Assets/TextMesh Pro/Resources/TMP Settings.asset` 引用。
- 当前工作区把两份 atlas 的序列化纹理改为 1×1、字符/字形表清空。`Twinkly SDF` 从 1024×1024 atlas 及 1 个缓存字形变为空；`en SDF` 从 299 个缓存字形/字符和多 atlas 状态变为空。
- 静态 GUID 扫描显示：`Twinkly SDF` 被 27 个 prefab/asset/scene 直接引用，`en SDF` 被 175 个资源直接引用，覆盖主界面、Loading、设置、商店、主线 HUD、Draw、IWanner 和胜利/提示 UI。

### 当前行为与保留边界

- 两份资产都设置 `m_ClearDynamicDataOnBuild: 1`，且源 TTF 存在；这为运行时按需重建提供了静态条件，不能仅凭缓存清空断言文字必然丢失。
- 仍需保护：多语言字符覆盖、首帧字形生成、fallback 顺序、材质/描边引用、低端机内存与 GC 表现。

### 风险链与验证基线

`TMP Settings / prefab 字体引用 → 动态 TMP_FontAsset → 源 TTF / fallback → 首次字形生成与 atlas 扩容 → UI 文本显示、布局和内存峰值`

- 已验证：动态模式、源 TTF 存在、fallback 与引用数量的静态检查。
- 未验证：Unity 导入、Player 打包后源字体可用性、多语言视觉、首帧卡顿、atlas 扩容和移动端内存。
