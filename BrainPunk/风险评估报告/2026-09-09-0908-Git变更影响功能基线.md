## 本轮功能基线

### ShopReward 与 IAP

- `Shop.rewards` 当前基线已经从单值/字典类读取迁移为有序 `List<ShopReward>`；`Assets/Configs/Code/Shop.cs:25` 反序列化数组，`Assets/Configs/Code/Shop.cs:57` 暴露列表。
- `ShopReward` 允许同类型重复奖励，`Assets/Configs/Code/ShopReward.cs:30` 明确“同类型可配置多项”，`ShopRewardUtils.TryGetTotal(...)` 只对 `IntParam` 做数量合计，不能用于 Skin。
- `PurchaseManager.OnPurchaseSuccess(...)` 进入 `OnPurchase(productName, shopData.Rewards)`；当前 `OnPurchase(...)` 只直接发放 `NoAds` 与 `UnlimitTips`，Coin/Skin 由 ShopPanel、ChestGift 等入口做补充交付。
- `PurchaseManager.TryRestorePurchase(...)` 只接受 `Possessive` 商品，恢复时跳过 Coin，逐项恢复 Skin/NoAds/UnlimitTips，并写 `PurchaseCache`。
- 风险判断基线：新客户端代码、`tbshop.json`、`#Shop.xlsx` 与 `shop_reward.xml` 必须成套发布；旧客户端单独接收新 JSON 属于不兼容场景。

### ChestGift 与启动弹窗

- ChestGift 商品由 `ChestGiftOfferResolver` 从 `TbShop.ChestPrefab`、`TbProducts.RewardId`、平台 SKU 和奖励列表联合校验。
- `ChestGiftController.TryPurchase(...)` 负责发起 IAP，并在回调成功后调用 `PurchaseManager.OnPurchaseSuccess(productName, showTips:false)` 写购买缓存，再用 `TryDeliverRewards(...)` 补发 Coin/Skin。
- `ChestGiftPopup` 只承担展示、奖励项布局、皮肤预览和金币飞行动画；同部位多 Skin 预览只展示第一件，但奖励项仍逐项展示与发放。
- `LoadManager` 启动弹窗链会等待 `StartPanel.WaitForEnterAnimationAsync(...)` 后再尝试打开 ChestGift；StartPanel 点击遮罩只应在进场动画完成后释放。

### ShopPanel、ShopRewardTip 与 GameTips

- ShopPanel 普通购买路径会调用 `PurchaseManager.OnPurchaseSuccess(...)`，随后调用 `ApplyPurchaseCoinReward(...)` 补发 Coin 并播放 Coin 动画。
- ShopPanel 的自动奖励提示 `ShopRewardTipPopup` 仍读取 `shop.Rewards.First().Value` 作为数量展示入口之一；重复奖励或非 Coin 商品需要额外核对。
- GameTips 当前基线已经从广告跳关改为金币路径：金币不足打开 `CoinGiftPopup`，金币足够则主线通过或 DrawGame 强制胜利。
