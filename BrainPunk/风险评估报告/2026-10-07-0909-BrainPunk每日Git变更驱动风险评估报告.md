## 变更入口到影响链路

### 链路 A：Android 广告依赖

`mainTemplate.gradle / AndroidResolverDependencies.xml`
→ Gradle 选择 FusionAds 1.5.2
→ Guru AdsManager 初始化与广告生命周期观察者
→ `GameAdsController`
→ `GameAdsManager`
→ `GameSDKService`
→ `InterstitialAdHelper / RewardAdHelper`
→ 主线、Draw、IWanner、Dig、礼包、商店等入口
→ 展示、失败/取消、奖励、广告计数、原生覆盖后的输入/遮罩恢复。

影响原因：这是实际 Android 二进制版本入口，而不是固定“广告模块扫描”得到的泛化风险。任何初始化或回调语义变化都会沿公共包装层扩散到所有广告消费者。

### 链路 B：首页两个 Dig 入口与重入

两个激活 `DigGameEnter` 实例
→ 每个实例 `OnEnable → Refresh → enterButton.OnClick += Enter`
→ 第一次点击 `TryEnterDig` 激活 Dig 并令 `_transitioning=true`
→ 转场完成前点击另一个入口
→ `PlayControllerManager` 发现 Dig 已活动而返回成功
→ `DigPlayCtrl.TryEnterCurrentLevel` 因 `_transitioning` 返回失败
→ `GameManager.TryEnterDig` 调用 `ReturnToStartPanel`
→ Dig `Deactivate` 增加版本并清理/取消当前转场。

影响原因：新增 Prefab 实例绕过单个 `CustomButton` 的实例内延迟门禁，把一个首页资源改动扩散成 Controller 状态回退问题。

### 链路 C：Dig Level 1 与相机

`tbdiglevelsort 1 → 40001`
→ `tbdigleveldata 40001 → DigLevel_001`
→ `DigPlayCtrl` 从 AssetBundle/ResourceManager 加载 Prefab
→ 成功加载后关闭持久 StartCamera
→ 实例化带 MainCamera 标签和 URP AdditionalCameraData 的 Dig Camera
→ `DigLevelCtrl.inputCamera` 处理挖掘坐标
→ Normal 层 Dig HUD 与关卡相机共同渲染
→ 失败通过返回首页链恢复 StartCamera。

影响原因：Main 根 Camera 同时改为失活，玩家画面最终由多台不同来源相机和 UI Canvas 排序共同决定；静态引用正确不等于实际 URP/HUD 结果已验收。

### 链路 D：TMP 动态字体缓存

FontAsset 缓存表/atlas 清空
→ Prefab/TMP_Text 引用同一 FontAsset
→ 冷启动首次遇到字符时从内嵌 TTF 动态生成 glyph
→ atlas 写入、纹理增长和潜在 GC/主线程耗时
→ 首页、关卡 HUD、弹窗、结算与多语言文本。

影响原因：`Twinkly SDF` 被大量资源复用，单个资源差异会跨 UI/关卡扩散；源字体存在是缓解，不是 SBP 与设备性能验收。
