# BrainPunk 核心模块功能基线

生成时间：2026-04-30 16:31:43 +08:00  
用途：作为每日风险评估的功能对照基线。后续扫描应优先对照入口、触发链路、回调语义、持久化字段和核心资源路径是否变化。

## 范围

| 模块 | 主要入口 | 主要职责 |
|---|---|---|
| 广告 | `GameSDKService.Ads`、`GameAdsManager`、`GameAdsController`、`InterstitialAdHelper`、`RewardAdHelper`、`InterstitialAdPolicy` | Guru/MAX 广告 SDK 初始化、插屏/激励视频展示、等待弹窗、展示结果回调、插屏触发策略记录 |
| 界面弹窗 | `Bear.UI.UIManager`、`GameTipsPopup`、`WaitingPopup`、`GameVictoryPanel`、`GameSettingPopup`、`CommmonPopup` | UI 加载/复用/栈管理、遮罩、暂停恢复、广告等待、胜利和确认弹窗 |
| 游戏主线核心流程 | `LoadManager`、`HotReloadCtrl`、`PlayCtrl`、`LevelCtrl`、`BaseLevelCtrl`、`EnterLevelLoading`、`ResourceManager` | 启动加载、热更新、配置加载、资源系统初始化、进关/重开/通关/下一关 |
| 打点数据统计 | `GameSDKService.Game`、`GameSDKService.Analytics`、`GameAnalytics`、`GameAttribute`、`SimpleBag`、`LevelRuntimeState` | 关卡开始/结束、买量点、道具获取/消耗、虚拟货币、用户属性、时长/次数累计 |

## 广告模块

### 初始化

- `GameSDKService.InitService` 先 `GuruSdk.PrepareEnv()`，再创建 `GameAdsManager`，最后 `GuruSdk.Initialize(...)`。
- `GameProtocol` 将 `GameAdsSpec.Instance` 注入 Guru SDK，`GameAdsSpec.BuildAdsSdk` 使用 `MaxGuruAds.Instance` 构建广告实现。
- `GameSDKService.IsInitialized` 当前有私有 setter，但初始化成功后未见赋值；项目实际广告 ready 更多依赖 `GameAdsManager.IsAdsInitialized`。
- `GameAdsController` 监听 Guru `AdsManager` ready 后绑定插屏和激励视频，并请求预加载。

### 插屏广告

- 业务入口：`InterstitialAdHelper.TryToShowInterstitial(placement, onResult)`。
- 支持广告位：`InGameFailed`、`InGameVictory`、`GameTest`。
- 展示前依赖 `PlayCtrl.Instance.InterstitialAdPolicy.CanShowInterstitial(currentLevel, placementType)`。
- 策略字段来自 `ConfigManager.RemoteConfig`，远端缺失时回退 `GlobalConst`：
  - `ad_interstitialCD`
  - `ad_rewardResetInterstitialCD`
  - `ad_interstitialShowMinLevel`
  - `ad_interstitialShowIntervalCount`
  - `ad_interstitialShowFailedCount`
- 成功播放后派发 `PlayInterstitialAdEvent`，记录 `DB.GameData.LastInterstitialDate`，并按场景重置失败或通关计数。

### 激励视频

- 业务入口：`RewardAdHelper.TryToShowRewardAd(placement, success, failed, onResult)`。
- 支持广告位：`InGameTips`、`InGamePassLevel`、`OutGameUnlockLevel`、`GameTest`。
- 调用 `GameSDKService.Instance.ShowRewardAd`，传入 `WaitingPopup.WaitingAdLoad` 作为等待弹窗。
- 成功后展示成功文案、派发 `PlayRewardADEvent`，并通过 `InterstitialAdPolicy` 记录 `LastRewardAdDate` 以抑制激励后插屏。
- `WaitingPopup` 默认 10 秒自动关闭，关闭时触发静态取消回调 `WaitingPopup.SetOnCancel`。

## 界面弹窗模块

### UIManager

- `UIManager.Instance` 为全局单例，未初始化时 `OpenUI` 自动 `Initialize()`。
- `OpenUI<T>(path, layer, isShowMask, isCloseByMask)`：
  - 通过 loader 加载并实例化 prefab。
  - 同 key UI 复用实例；若当前层栈顶已是同 UI，则直接返回。
  - 新 UI 入栈前隐藏同层旧栈顶。
  - Popup/Top 层显示遮罩。
- `CloseUI(this)` 只关闭当前层栈顶；目标不是栈顶时会忽略。
- `CloseAllUI(layer)` 弹出整层 UI 并调用 `OnHide`、`OnClose`。
- `DestroyUI(this)` 会从栈和实例字典移除并销毁 GameObject。

### 主要弹窗

- `GameTipsPopup`
  - `OnShow` 派发 `SwitchGameStateEvent(PAUSE)`。
  - 正常关闭派发 `SwitchGameStateEvent(PLAYING)`。
  - 普通提示消耗 `Tips`；不足时打开缺少道具状态；已有提示后进入直接通关提示状态。
  - 激励视频成功后增加 `Tips` 或直接进入成功状态。
- `WaitingPopup`
  - 用于激励视频加载等待。
  - 默认 10 秒自动关闭并触发取消。
  - 使用静态 `_onCancel` 和 `RewardAdHelper.CancelCurrent` 结束等待任务。
- `GameVictoryPanel`
  - 打开时禁用 Next。
  - 当前版本已对 `spineCtrl == null`、动画返回空、tips key 空、翻译空、`DOText` 未完成增加兜底，避免 Next 永久不可点。
  - `Next` 关闭自身并派发 `EnterNextLevelEvent`。
- `GameSettingPopup`
  - 游戏中打开时可显示菜单按钮。
  - 关闭时如果 `isPlaying` 为 true，派发 `PLAYING`。
  - 退出关卡时派发 `FAILED` 并打开选关面板。
- `CommmonPopup`
  - Yes/No 使用 `CloseUI(this)` 后触发业务回调。
  - 关闭按钮使用 `DestroyUI(this)`，不触发业务回调。

## 游戏主线核心流程

### 启动流程

`LoadManager.Awake` 将流程按顺序加入队列：

1. `EnterGame`
   - `booster.Init`
   - `GameManager.Instance.Init`
   - `DBManager.Instance.Initialize`
   - 初始化语言
   - `DB.GameData.PlayCount++`
2. `HotReload`
   - 订阅热更新事件
   - `HotReloadCtrl.Instance.Init(packageName, playMode)`
   - 等待 `HotReloadCtrl.Instance.IsFinish && booster.IsReady`
3. `LoadConfigAsync`
   - 拉取 RemoteConfig
   - 初始化 `ConfigManager`
4. `OnPostProcess`
   - 初始化 `UIManager`
   - 注册 `ResourcesUILoader`
   - `ResourceSystemInitializer.Initialize`
   - 初始化音频、IAP、用户属性、PlayCtrl、成就
5. 加载 `Main` 场景

### 热更新状态机

状态顺序：

1. `INITIALIZE_PACKAGE`
2. `REQUEST_PACKAGE_VERSION`
3. `UPDATE_PACKAGE_MANIFEST`
4. `CREATE_DOWNLOADER`
5. `DOWNLOAD_PACKAGE_FILES`
6. `DOWNLOAD_PACKAGE_OVER`
7. `CLEAR_CACHE_BUNDLE`
8. `START_GAME`

`START_GAME` 调用 `owner.SetFinish()`，`LoadManager` 才能退出热更新等待。

### 进入关卡

- `PlayCtrl.Init` 初始化 `LevelCtrl`、`SimpleBag`、`InterstitialAdPolicy`、状态机和事件订阅。
- `EnterLevelEvent`：
  - `Level.SetCurrentLevel(sortId)`
  - `Level.CurrentLevelState.StartLevel(sortId, data.Path)`
  - 首关首次进入先显示漫画弹窗
  - `EnterLevelLoading.Create` 回调中 `DestroyLevel`、`CreateLevelAsync`，成功才进入 `PLAYING`，失败打开 `ChoiceLevelPanel`
- `CreateLevelAsync(levelName)`：
  - 路径格式 `Assets/Game/Prefabs/Level/{0}.prefab`
  - 通过 `Bear.ResourceSystem.ResourceManager.Instance.LoadAsync<GameObject>` 加载
  - 实例化到 `SceneRoot`
  - 根据 `LevelCtrl.GamePlayPanelName` 创建玩法面板

### 失败、重开和通关

- `BaseLevelCtrl` 监听陷阱/失败区域事件。
- 失败后派发 `GameResetEvent(GameResetType.Failed)`。
- `PlayCtrl.OnGameResetEvent`：
  - 记录失败或手动重开
  - 上报 `level_end(fail)` 和 `level_start(replay)`
  - 重置本次尝试时长
  - 进入 `ResetGame`
- `ResetGame`：
  - 关闭 Popup 层
  - 尝试播放失败插屏
  - 重建当前关卡
  - 进入 `PAUSE`，再进入 `PLAYING`
- `PlayCtrl_Success.OnEnter`：
  - `TryToAddSuccessCount`
  - 尝试通关插屏
  - 上报 `level_end(success)`
  - 可能显示评分弹窗
  - 显示 `GameVictoryPanel`
  - `Level.Victory` 更新已通关、最大关卡、解锁下一关并保存 DB

## 打点统计模块

### 统一发送

- `GameSDKService.LogEvent`、`LogEventWithOptions` 转发到 `GuruAnalytics.Instance.LogEvent`。
- `GameAnalytics` 配置 AppsFlyer transmitter，并定义 IAP 和部分 `level_end_success_n` 买量点。

### 关卡打点

- `LevelStartEvent(status)`：
  - `level_name` 使用 `Level.CurrentLevelData.Path`
  - `level` 使用 `GetLevelPassedCount() + 1`
  - `play_count` 使用 `LevelPlayCount + LevelReviveCount`
  - `start_type` 为 `play`、`replay`、`continue`
- `LevelEndEvent(status)`：
  - 先 `RecordLevelDuration`
  - `level` 使用 `passedCount`
  - `level_name` 使用当前关卡路径
  - `duration`、`level_duration` 使用当前关卡运行时长
  - `total_duration` 使用持久化累计时长
  - 成功时额外发送 `level_end_success_{count}`

### 道具和货币打点

- `SimpleBag.AddTool(GameProps, count, RewardType)`：
  - 修改 `DB.GameData.GameTools`
  - Tips 来源为广告或购买时更新 `AdGetTools` / `PurchaseGetTools`
  - 发送 `bulbs_get`
  - 发送 `earn_virtual_currency`
- `SimpleBag.RemoveTool(GameProps, count, CostType)`：
  - 修改 `GameTools`
  - Tips 消耗时发送 `bulbs_cost`
  - 发送 `spend_virtual_currency`
  - 记录 `ToolConsumesCache`
  - 尝试刷新消耗类成就

## 持久化字段

核心数据位于 `DB.GameData`：

| 字段 | 用途 |
|---|---|
| `CurrentLevel` | 当前关卡排序 ID |
| `MaxLevel` | 最大解锁/通关进度 |
| `UnlockLevels` | 已解锁关卡 |
| `PassedLevels` | 已通过关卡 |
| `GameTools` | 道具余额 |
| `PurchaseCache` | 购买次数缓存 |
| `ToolConsumesCache` | 道具消耗次数 |
| `LastInterstitialDate` | 最近一次插屏播放时间 |
| `LastRewardAdDate` | 最近一次激励视频播放时间 |
| `InterstitialFailCount` | 插屏失败场景触发计数 |
| `InterstitialLevelSuccessCount` | 插屏通关间隔计数 |
| `LevelPlayCount` | 关卡开始次数 |
| `LevelSuccessCount` | 关卡成功次数 |
| `LevelReviveCount` | 关卡失败/重开次数 |
| `LevelPlayDuration` | 关卡累计游玩时长 |
| `RemoteConfigCache` | 远端配置缓存 |
| `AdGetTools` | 广告获得道具累计 |
| `PurchaseGetTools` | 购买获得道具累计 |
| `HasComics` | 首关漫画是否已显示 |

## 后续每日对照重点

- 广告：placement、RemoteConfig 字段、SDK 初始化状态、激励等待取消、回调是否只触发一次。
- 弹窗：所有暂停游戏的弹窗关闭路径是否恢复 `PLAYING`；UI 加载失败是否会留下遮罩或卡住主流程。
- 主流程：热更新失败是否能退出；资源加载异常是否被捕获；进关、重开、下一关是否都按加载结果 gate。
- 打点：`level`、`level_name`、`play_count`、`duration`、`revive`、虚拟货币余额是否与业务定义一致，是否存在重复事件或多计数。
