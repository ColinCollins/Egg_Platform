## 3. DrawGame 存档、DailyChallenge 与打点基线

当前 `DB.DrawGame` 保存 DrawGame 独立状态：

- 当前关卡：`CurrentLevel`
- 解锁/通关：`UnlockLevels`、`PassedLevels`
- 星级：`LevelCollectedStar`、`LevelWaitingAnimStar`
- 插屏：`LastInterstitialDate`、`LastRewardAdDate`、`InterstitialFailCount`、`InterstitialLevelSuccessCount`
- 打点计数：`LevelStartCount`、`LevelRetryCount`、`LevelSuccessCount`

当前链路：

```text
DrawPlayCtrl.OnLevelResolved(Success)
  -> RecordLevelSuccessAnalytics
  -> DailyChallenge.TryRecordVictory(-DrawLevelSort.Id)
  -> ReportLevelEndAnalytics(success)
  -> DrawGame_GameVictoryPanel / Reward panel
  -> RecordVictoryProgress
  -> DB.SaveDrawGame
```

`GameSDKService.Game.cs` 已新增 Draw 专用 `DrawLevelStartEvent` 与 `DrawLevelEndEvent`，事件名仍为 `level_start` / `level_end`，但增加 `item_category = draw`，且 Draw 成功不触发主线 `level_end_success_N` 买量事件。

风险基线：

- Draw 与主线可能有相同关卡序号，当前 DailyChallenge 用负数键隔离当日去重空间，这是明确缓解。
- Draw 打点仍写同名 `level_start` / `level_end`，依赖 `item_category` 区分；后台报表若未按字段拆分，仍可能污染主线口径。
- `DB.SaveDrawGame()` 在成功、重试、打点和星级保存中多次调用，保存失败路径主要记录日志或局部回滚，PlayMode 未验证。
