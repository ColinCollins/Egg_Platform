## 1. GameTips / DrawGame Tips 与金币礼包链路

### 已确认事实

- `GameTipsPopup` 在打开时重置 `_hasClickedConfirmButton`，金币或广告确认按钮路径会将该标记置为 `true`。
- 主线 `GameTipsPopup.Close` 只有在“非确认按钮关闭”且金币不足时才尝试打开 `CoinGiftPopup`，并在普通关闭路径恢复 `GameState.PLAYING`。
- `DrawGame_GameTipsPopup` 也引入同类确认标记，非确认关闭路径才尝试打开金币礼包；通过金币/广告继续或胜利请求时会把标记置为 `true`。
- `DevelopMD/GameTips_Logic.md` 与 `Assets/Game/UI/GameTipsPopup/Scripts/DrawGame_GameTipsPopup功能与风险评估.md` 均记录了 2026-09-10 的关闭后金币礼包行为，但仍标记 PlayMode、Android/iOS、广告覆盖层和金币礼包弹层联动未验证。

### 功能边界

- Tips 弹窗负责决定关闭时是否补开金币礼包；金币礼包本身由 `CoinGiftPopup.Create` 与 Gift/IAP/广告链路承接。
- 该链路跨越 UI 关闭、游戏暂停/恢复、金币余额、广告/购买、弹层遮罩与输入恢复；任何“重复打开”“关闭时序提前”“恢复状态提前”都可能放大为主流程卡住或支付/广告回调错位。

### 回滚锚点

- 回滚到确认按钮标记前的实现会恢复“关闭提示时可能再次打开金币礼包”的旧行为，但也可能重新引入确认后重复弹礼包的问题。
- 更安全的回滚方式是在保留确认标记的前提下，限制金币礼包触发入口或增加 PlayMode/真机验证后的局部条件。

## 2. ChestGift / Shop 折扣与购买链路

### 已确认事实

- `ChestGiftPopup.ConfigureOffer` 接收 `ChestGiftOfferViewData` 后调用 `RefreshOffer`，折扣显示由 `SetDiscount(offer.ShopDiscount)` 控制。
- `SetDiscount` 对 `discountPercent > 0` 显示折扣文案，`0` 或不可用商品时隐藏折扣节点。
- `ChestGiftPopup` 仍通过 `PurchaseManager.TryGetProductId`、`GetPrice`、`IsInitialized` 等接口解析价格和可购买状态。
- `Assets/Game/UI/GiftPopup/Scripts/ChestGiftPopup功能与风险记录.md` 记录了 2026-09-10 折扣标记接入：价格、购买、奖励流程不应改变，但 PlayMode、Android/iOS、真实商品价格和多语言视觉仍未覆盖。

### 功能边界

- ChestGift 弹窗只展示当前礼包 offer，不应直接改变 Shop 表、购买结果、奖励发放或 Gift 刷新策略。
- 折扣文案来自配置，属于 UI 展示链路；价格与购买是否可用仍以 PurchaseManager 和商品映射为准。

### 回滚锚点

- 可局部回滚 `SetDiscount` 的展示逻辑或将 `ShopDiscount` 视为只读展示字段，不应回滚购买解析、价格解析和 Gift 入口。
