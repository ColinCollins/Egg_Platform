### 2. `LoadManager.cs` / `ScheduleSystem.cs` / `InterstitialNOAdPopupAutoShowModule.cs` 为什么会影响每日次数控制

- 改动意图：新增通用 `ScheduleSystem`，并把插屏后的 `NoAdsPopup` 自动展示次数纳入按日重置。
- 影响模块：广告/IAP、持久化数据、启动链、远端配置。
- 扩散链路：
  `LoadManager.EnterGame -> ScheduleSystem.RegisterModule(Daily) -> ScheduleSystem.CheckAllModules`
  `InterstitialAdHelper static field -> InterstitialNOAdPopupAutoShowModule.Create -> Init -> DailyScheduleModule.Register(this)`
  `ShouldShowNoAdPopup -> DB.GameSchedule.Daily_interstitialNoAdPopupShowCount / ConfigManager.RemoteConfig.GetAdDailyNOAdPopupAutoShowCount`
- 风险扩散原因：注册点不在启动链，而是在 `InterstitialAdHelper` 第一次被 CLR 初始化时才发生。只要首次插屏之前从未引用过 `InterstitialAdHelper`，当天的 `CheckAllModules()` 就不会覆盖这个模块，昨天残留的次数会直接沿 `GameSchedule` 带到今天。

### 3. `InterstitialAdHelper.cs` / `NoAdsPopup.cs` 为什么会影响 IAP 来源打点

- 改动意图：插屏成功后主动带出免广告购买弹窗。
- 影响模块：IAP 打点、商店来源归因、广告转化漏斗。
- 扩散链路：
  `InterstitialAdHelper.TryToShowInterstitial(success) -> NoAdsPopup.Create() -> lastUIName 默认 ChoiceLevelPanel -> GameSDKService.IAP_IMP("ChoiceLevelPanel") / IAP_CLOSE("ChoiceLevelPanel")`
- 风险扩散原因：自动弹窗的来源没有从插屏调用点往下透传，导致 `iap_imp/iap_close` 事件继续沿用关卡选择页的默认分类，后续报表会把插屏转商店误归到 `ChoiceLevelPanel`。

### 4. `ProjectSettings.asset` / `StartPanel.cs` / `GMPanel.prefab` / `PageView.cs` 为什么会影响启动流程和调试暴露面

### 5. `Assets/GF` / `korean SDF.asset` 为什么会影响多语言文本与动画显示

- *影响文件*：`ProjectSettings/ProjectSettings.asset`、`Assets/Game/UI/StartPanel/Scripts/StartPanel.cs`、`Assets/Game/UI/GM/Resources/GMPanel.prefab`、`Assets/Game/UI/PageView/Scripts/PageView.cs`、`Assets/Game/UI/GM/Scripts/DebugModeSwitchAllBtns.cs`

### P1-2 `InterstitialNOAdPopupAutoShowModule` 的每日 reset 注册时机滞后

- *问题*：`DailyScheduleModule` 在 `LoadManager.EnterGame()` 里启动即执行 `CheckAllModules()`，但 `InterstitialNOAdPopupAutoShowModule` 只在 `InterstitialAdHelper` 的静态字段初始化时才 `Create()->Init()->Register(this)`。如果当天首次插屏之前从未触发过 `InterstitialAdHelper` 类型初始化，这个模块会错过当日 reset，昨天的 `Daily_interstitialNoAdPopupShowCount` 会继续被今天读取。
- *影响文件*：`Assets/Game/UI/Loading/Scripts/LoadManager.cs`、`Assets/Game/Scripts/Schedule/ScheduleSystem.cs`、`Assets/Game/Scripts/Runtime/Ads/InterstitialAdHelper.cs`、`Assets/Game/Scripts/Runtime/Ads/InterstitialNOAdPopupAutoShowModule.cs`、`Assets/Game/DB/GameSchedule.cs`、`Assets/Game/DB/GameSchedule_Partial.cs`
- *建议*：把 `InterstitialNOAdPopupAutoShowModule` 的注册前移到启动链，例如在 `LoadManager` 或广告系统显式 `Init()`；或者在 `ShouldShowNoAdPopup()` 里增加“当前自然日 vs 上次刷新日”兜底校验，避免 stale 计数跨天滞留。
- *Git 依据*：提交 `254c1f54` 新增 `ScheduleSystem` 与 `DailyScheduleModule`；提交 `6c17752c` 再把 `InterstitialNOAdPopupAutoShowModule` 挂到 `InterstitialAdHelper` 的静态字段上。
- *扩散链路*：`LoadManager.CheckAllModules(早) -> InterstitialAdHelper.Create(晚) -> Daily 模块没接到 reset -> DB.GameSchedule.Daily_interstitialNoAdPopupShowCount 残留 -> ShouldShowNoAdPopup 判断漂移`

### P1-3 自动弹出的 `NoAdsPopup` 会把 IAP 来源误记成 `ChoiceLevelPanel`

- *问题*：`InterstitialAdHelper` 在插屏成功后调用的是 `NoAdsPopup.Create()` 默认重载，而 `NoAdsPopup.Create(string lastUIName = "ChoiceLevelPanel")` 会立刻打 `IAP_IMP/ IAP_CLOSE`。这意味着自动弹出的免广告购买窗会把来源打成 `ChoiceLevelPanel`，而不是 `Interstitial` 或真实 placement。
- *影响文件*：`Assets/Game/Scripts/Runtime/Ads/InterstitialAdHelper.cs`、`Assets/Game/UI/NoAds/Scripts/NoAdsPopup.cs`、`Assets/Game/Scripts/SDK/Services/Events/GameSDKService.IAP.cs`
- *建议*：给 `NoAdsPopup.Create()` 传入明确来源，如 `Interstitial_InGameVictory` / `Interstitial_InGameFailed`；同时补一条自动弹窗专用埋点，避免和关卡选择页商店曝光混桶。
- *Git 依据*：提交 `6c17752c` 新增 `InterstitialAdHelper -> NoAdsPopup.Create()` 自动调用；当前 `NoAdsPopup.Create` 默认参数仍是 `ChoiceLevelPanel`。
- *扩散链路*：`Interstitial success -> NoAdsPopup.Create(default ChoiceLevelPanel) -> GameSDKService.IAP_IMP/IAP_CLOSE -> 商店来源归因被写错 -> 插屏转商店漏斗失真`
