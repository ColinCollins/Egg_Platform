## P0 风险

### P0-1 Level999 启动即累加通关次数，污染成就和关卡统计

- *问题*：最近 Level999 成就修复新增 `Level999Ctrl.Start()` 直接执行 `DB.GameData.LevelSuccessCount[data.Path]++` 并保存，随后触发 Level/LevelCount 成就检查。该入口没有经过 `BaseLevelCtrl.Victory` 或 `PlayCtrl` 的通关结算路径，也没有首通/重复进入保护。玩家进入、重载或异常重建 Level999 时，都可能重复增加通关次数，导致成就提前解锁、通关统计多计数，并污染后续打点判断。
- *影响文件*：`Assets/Game/Scripts/Level/LevelItem/Level_999/Level999Ctrl.cs:8-25`、`Assets/Game/Scripts/SDK/Services/Account/GameAchievementUtils.cs:274-280`
- *建议*：将 Level999 统计写入收敛到统一通关结算入口；如果 Level999 必须特殊处理，至少增加当前关卡已结算标记、首通判断、重复 Start 防护，并补充一次“重复进入 Level999 不重复加计数”的验证。

### P0-2 激励广告 TimeScale 临时修复破坏全局暂停语义

- *问题*：最近 rewardAd 加载修复在 `RewardAdHelper` 中直接设置 `Time.timeScale = 1`，3 秒后仅在 `PlayCtrl` 仍处于 PAUSE 时改回 0；同时 `PlayCtrl_Pause` 中原本的 `Time.timeScale = 0/1` 已被注释。结果是暂停状态不再稳定约束 Update/Time.time 逻辑，广告等待期间或弹窗关闭后，依赖 `Time.time`、`Time.deltaTime`、输入拖拽的关卡行为仍可能继续运行。`6593095c` 已出现“暂停可以擦除”的相关修复，说明该风险已在具体关卡暴露。
- *影响文件*：`Assets/Game/Scripts/Runtime/Ads/RewardAdHelper.cs:62-95`、`Assets/Game/Scripts/Play/PlayCtrl_Nodes/PlayCtrl_Pause.cs:14-39`、`Assets/Game/Scripts/Effects/SceneSpriteBrushClear.cs`、`Assets/Game/Scripts/Level/LevelItem/Level_44/Level44Ctrl.cs:203-231`
- *建议*：不要由广告工具直接持有全局 TimeScale 恢复策略；改为广告 SDK 等待使用 unscaled time 或独立超时源，游戏暂停仍由 `PlayCtrl_Pause` 统一控制。对 Level44/46 等 Update 驱动关卡补一次“暂停 + 广告等待 + 拖拽/擦除不可继续”的回归验证。

### P0-3 Loading 转场异常路径可卡住或跳过关卡加载失败

- *问题*：最近 Loading 转场修复让 `EnterLevelLoading` 等待 `_onPageTurnComplete`，但回调之后直接访问 `_graphsic.transform.SetParent(_brushEffect.transform)`，没有保护 `_graphsic` 或 `_brushEffect` 为空。`StartEraseSequence()` 先派发 PAUSE，再发现路径为空时只 `CloseSelf()`，没有恢复 PLAYING。另一方面，`PlayCtrl.EnterGame/OnEnterNextLevel` 在 `CreateLevelAsync` 返回后无论关卡 prefab 是否加载成功都会进入 PLAYING，而 `CreateLevelAsync` 在 `LevelPrefab` 为空时只是记录 `Level lost` 并 return。组合后会出现转场关闭、状态切换、关卡实例缺失三者不一致，最坏会卡主流程或进入空关卡。
- *影响文件*：`Assets/Game/UI/Global/Scripts/EnterLevelLoading.cs:121-147`、`Assets/Game/UI/Global/Scripts/EnterLevelLoading.cs:160-170`、`Assets/Game/UI/Global/Scripts/EnterLevelLoading.cs:318-334`、`Assets/Game/Scripts/Play/PlayCtrl.cs:135-140`、`Assets/Game/Scripts/Play/PlayCtrl.cs:162-167`、`Assets/Game/Scripts/Play/PlayCtrl.cs:263-283`
- *建议*：让 `CreateLevelAsync` 返回 bool 或抛出可控错误，只有加载成功才进入 PLAYING；`EnterLevelLoading` 的空资源/路径失败路径必须成对恢复状态并关闭 UI；转场关键引用缺失时记录明确错误并走失败兜底。

### P0-4 Level45 新功能依赖 prefab 绑定且缺少空保护，可能阻断关卡主流程

- *问题*：最近三天 Level45 prefab 和 `Level45Ctrl` 高频修改，新增交互依赖当前 GamePlayPanel、Use 按钮、wallCrash、shakePlayer、keyDirect、MoveFloatHandle 等绑定。当前 `Start()` 直接链式取 `PlayCtrl.Instance.CurrentGamePlayPanel.GetComponent<GamePanel_UseBtnCommonFeature>()` 并订阅 `Use_btn`，`ClickWall()` 在 `wallCrash != null` 时直接调用 `shakePlayer.PlayFeedbacks()`，`StopKey()` 直接访问 `keyDirect` 和 `MoveFloatHandle`。任意 prefab 绑定遗漏都会 NRE，导致 Level45 交互中断或无法通关。
- *影响文件*：`Assets/Game/Scripts/Level/LevelItem/Level_45/Level45Ctrl.cs:50-56`、`Assets/Game/Scripts/Level/LevelItem/Level_45/Level45Ctrl.cs:179-200`、`Assets/Game/Scripts/Level/LevelItem/Level_45/Level45Ctrl.cs:235-248`、`Assets/Game/Prefabs/Level/Level_045.prefab`
- *建议*：为 Level45Ctrl 增加启动时依赖校验和降级日志；所有可选特效引用使用空保护；把 prefab 必填引用纳入编辑器校验，至少覆盖 Level45 首次进入、点击墙、StopKey、通关路径。

## P1 风险

### P1-1 Android 自动登录一次性标记会把临时失败固化

- *问题*：最近 Android Login 防多次弹窗改动在非强制登录时，调用认证前就写入 `DB.GameSetting.HasTryingGoogleLogin = true` 并保存。若 `ManualAuthenticateAsync()` 抛异常或 Google Play Games 临时失败，后续 `TryAutoLoginGame()` 会直接返回 false，不再尝试自动登录。用户只有进入成就页走 `LoginWithGame(true)` 才可能重新触发，导致成就、云/平台服务入口表现不稳定。
- *影响文件*：`Assets/Game/Scripts/SDK/Services/Account/GameAccountUtils.cs:54-93`、`Assets/Game/Scripts/SDK/Services/Account/GameAccountUtils.cs:146-162`、`Assets/Game/UI/LevelChoicePanel/Scripts/ChoiceLevelPanel.cs:161-199`
- *建议*：区分“已展示自动弹窗”和“登录成功/失败原因”；认证异常时允许冷却后重试，或记录失败码并在下次启动重新判断。成就入口应提示登录失败原因，而不是静默返回。

### P1-2 激励广告未初始化时仍可能进入等待弹窗

- *问题*：`GameAdsManager.ShowRewardAd()` 只在 `!IsAdsInitialized && loadingDialog == null` 时快速失败；而 `RewardAdHelper` 始终传入 `loadingDialog`，因此广告未初始化时仍会继续调用 `_adsController?.ShowRewardedAd(...)` 并打开等待弹窗。若 `_adsController` 为空或 SDK 没有回调，用户体验会依赖 `WaitingPopup` 的超时/取消兜底，容易被误判为广告卡死。
- *影响文件*：`Assets/Game/Scripts/SDK/Services/Ads/GameAdsManager.cs:145-171`、`Assets/Game/Scripts/Runtime/Ads/RewardAdHelper.cs:64-77`、`Assets/Game/UI/Global/Scripts/WaitingPopup.cs`
- *建议*：无论是否传入 loadingDialog，广告未初始化都应立即失败并给出统一提示；等待弹窗只用于“已发起加载但等待 SDK 返回”的状态，不应用来遮盖初始化失败。

### P1-3 Level44 使用通用 EventId=1，存在跨系统误触发风险

- *问题*：Level44 新增 `Level44GamePanelFeature`，点击 Use 按钮派发 `OnTiggerItemEvent(1)`；`Level44Ctrl` 只判断 `evt.EventId != 1` 就执行投掷逻辑。该事件没有携带关卡 ID、发送者或对象上下文，若同一面板/其他系统也使用 EventId=1，Level44 激活期间可能被非预期事件触发，造成重量、投掷次数或胜负条件异常。
- *影响文件*：`Assets/Game/Scripts/Level/LevelItem/Level_44/Level44GamePanelFeature.cs:16-27`、`Assets/Game/Scripts/Level/LevelItem/Level_44/Level44Ctrl.cs:84-88`、`Assets/Game/Scripts/Level/LevelItem/Level_44/Level44Ctrl.cs:150-155`
- *建议*：为关卡事件增加上下文，例如 levelId/sourceId/actionId；或至少在 Level44Ctrl 中校验当前关卡、当前 panel feature 和对象状态，避免全局数字事件直接驱动核心逻辑。

### P1-4 成就缓存加载被注释，重复解锁和状态判断缺少 SDK 侧去重依据

- *问题*：`GameAchievementUtils.LoadAchievementCacheAsync()` 中实际加载 SDK achievement cache 的逻辑被整体注释，`TryToAchievement_Level` 中 `IsAchievementUnlocked` 判断也被注释。最近 Level999 和 tips 成就计数修复都依赖该模块，当前只能根据本地 DB 条件不断请求 `UnlockAchievement` 或 `IncrementAchievement`，无法在本地过滤已解锁成就，容易出现重复请求、日志噪声和平台侧状态不一致。
- *影响文件*：`Assets/Game/Scripts/SDK/Services/Account/GameAchievementUtils.cs:75-102`、`Assets/Game/Scripts/SDK/Services/Account/GameAchievementUtils.cs:121-151`、`Assets/Game/Scripts/SDK/Services/Account/GameAchievementUtils.cs:244-280`
- *建议*：恢复或替代成就状态缓存；在 SDK 版本问题未解决前，至少增加本地成就触发记录，避免同一 achievementId 在同一存档中重复请求。
