## 变更入口到影响链路

### 链路 A：Daily 调度扩散到商店免费金币与插屏 NoAds 提示

- 入口文件：`LoadManager.cs`、`DailyScheduleModule.cs`、`GameSchedule.cs`
- 扩散路径：`LoadManager.EnterGame()` 注册 Daily 模块后，会在启动时立刻跑 `CheckAllModules()`；Daily 又持有 `InterstitialNOAdPopupAutoShowModule` 和 `ShopAdRewardTipAutoShowModule`，因此启动顺序、跨天重置、GM 调试页伪造跨天都会直接作用到两类自动弹窗。
- 风险特征：只要 `GameSchedule` 的时间戳或计数被错误推进，就会让“今天是否还能弹”“为什么现在突然弹”变成状态性故障，而不是单点 UI 问题。

### 链路 B：ShopPanel 从纯商店页扩散成经济、广告、自动弹窗交叉点

- 入口文件：`ShopPanel.cs`、`ShopRewardTipPopup.cs`、`tbshop.json`、`tbproducts.json`
- 扩散路径：`ShopPanel` 现在既处理 IAP，也处理激励视频，还在 `OnClose()` 里决定是否弹 `ShopRewardTipPopup("20000")`。商品表同时从旧 `hint*` 映射切到 `coin_pack_*` 与 `noad_bundle`，所以 reward、restore、售罄、埋点都被绑在一起。
- 风险特征：任何一处“旧商品语义未清干净”都会同时污染购买奖励、自动弹窗、售罄判断和恢复购买。

### 链路 C：胜利态插屏和 NoAdsPopup 从同一标记跨关扩散

- 入口文件：`PlayCtrl_Success.cs`、`InterstitialAdHelper.cs`、`PlayCtrl.cs`
- 扩散路径：成功态先打 `InGameVictory` 插屏；插屏成功只把 `HasInsterstitial` 设成 `true`；真正的 `NoAdsPopup.Create()` 延迟到下一次 `OnEnterNextLevel()` 时判定。
- 风险特征：如果“插屏成功”和“下一关进入”之间状态没有一一消费，NoAdsPopup 就会跨关滞留或在错误时机冒出来。

### 链路 D：Coin / UnlimitCoin 迁移扩散到 Tips、Shop、Victory 和默认新手经济
