## 变更入口到影响链路

### 1. FusionAds 1.5.2

`mainTemplate.gradle:65` / `AndroidResolverDependencies.xml:60` → Gradle/EDM4U 解析 → FusionAds AAR 1.5.2 → `GameSDKService` 广告能力 → `RewardAdHelper` / `InterstitialAdHelper` → 广告加载与原生覆盖 → 成功/失败/关闭回调 → Dig 奖励发放、插屏策略、输入恢复与收入。

当前包声明与只读 SDK 依赖文件均为 1.5.2，版本入口一致；本地 1.5.1 和 1.5.2 AAR 哈希不同，证明二进制发生变化。业务回调层的单次完成保护能降低重复发奖风险，但不能覆盖 SDK 初始化、AndroidX/Manifest 合并、裁剪、无填充、原生覆盖暂停和回调丢失。

### 2. StartPanel 双 Dig 入口

`StartPanel.prefab` 两个激活实例 → 两个 `DigGameEnter.OnEnable/Refresh` → 各自按钮独立 `isTrigger` → 第一次点击 `GameManager.TryEnterDig` → `DigPlayCtrl.BeginTransition` 将 `_transitioning` 置真 → 第二个按钮仍可点击 → `PlayControllerManager.TryEnter` 因已是 Dig 返回成功 → `DigPlayCtrl.TryEnterCurrentLevel` 因 `_transitioning` 失败 → `GameManager.TryEnterDig` 调用 `ReturnToStartPanel`。

这是由当前 Prefab 与源码共同支持的静态可达路径。`uncertain`：两个实例在目标分辨率是否同时可见，以及快速跨按钮点击能否稳定复现，尚未运行验证。

### 3. Dig Level 1 与 Main 相机

Dig 排序/数据配置 → `DigPlayCtrl.BuildLevelAsync` → ResourceManager 加载 `DigLevel_001.prefab` → 关闭持久化 StartCamera → 实例化带 `MainCamera` 标签和 URP Additional Camera Data 的关卡相机 → `DigLevelCtrl.InitializeRuntime` → 绑定相机的触控/射线 → 结算/重置/回首页重新打开 StartCamera。

同时，`Main.unity` 的场景 Camera 已失活。静态上 Loading 场景的持久化 StartCamera 能承接首页，关卡内部重序列化引用也可解析；但生命周期依赖更集中，缺少主项目 PlayMode 和 Android/iOS 横屏画面、触控、切关/回首页验证。

### 4. 动态 TMP 字体

`en SDF.asset` / `Twinkly SDF.asset` 动态表与额外 atlas 清理 → SBP/资源收集 → Loading 与通用 UI 加载 → 运行时首次字形请求 → 动态 atlas 回填 → 文本可读性、加载峰值和平台写入/纹理行为。

两份资产均为 Dynamic 并启用 build-time clear，源 TTF 存在；项目 HotReload 文档也把清理视为预期步骤。因此“表为空”等于“必然缺字”不成立。风险来自清理后尚无 SBP 和移动端实际渲染证据。

### 5. 诊断与编辑器元数据

`build_info` → Reporter 运行时显示构建来源；`guru_gf_settings.txt` → GF Booster 编辑器设置；孤立 `.old.meta` 删除 → GUID 引用检查。当前没有证据把它们扩散到玩家主流程，但 `build_info` 会进入 StreamingAssets，应避免将本地构建标识误当正式产物来源。

### P0-1 FusionAds 1.5.2 缺少 Android 发布链验证

- *问题*：发布实际依赖从 1.5.1 切到二进制不同的 1.5.2；静态声明已对齐，但没有清洁 Android 构建、最终依赖树、AAB/IL2CPP 和真机广告全回调证据。
- *影响文件*：`Assets/Plugins/Android/mainTemplate.gradle`、`ProjectSettings/AndroidResolverDependencies.xml`；受影响消费者包括广告服务、激励/插屏帮助类和 Dig 奖励入口。
- *建议*：清洁导出并构建 Android；确认最终依赖树只解析 1.5.2；真机覆盖初始化、加载成功/失败、无填充、展示、关闭、奖励、重复回调和原生覆盖返回后的输入恢复。SDK 内部异常应交由 GuruSDK 维护方，禁止改写只读 `Packages/`。
- *Git 依据*：上述两个工作区文件的 1.5.1 → 1.5.2 diff；最近三天没有包含构建/验证产物的业务提交。
- *扩散链路*：Gradle 依赖 → SDK 初始化/平台桥接 → 广告请求与原生覆盖 → 回调 → 奖励、策略、输入和收入。

## P1 风险

### P1-1 StartPanel 双 Dig 入口可打断首次进关

- *问题*：两个激活入口各自拥有独立按钮防抖。首次进入正在转场时，第二入口可再次请求；现有失败处理会回到首页。
- *影响文件*：`Assets/Game/UI/StartPanel/Resources/StartPanel.prefab`；调用链涉及 `DigGameEnter`、`CustomButton`、`PlayControllerManager`、`GameManager`、`DigPlayCtrl`。
- *建议*：保留一个有效入口并确保 `StartPanel.digGameEnter` 绑定该实例；PlayMode 验证目标分辨率只出现一个入口，并覆盖快速连点、跨位置点击、Loading 创建前后与回首页。
- *Git 依据*：Prefab 新增第二个同源实例，静态计数为 2，原字段仍绑定旧实例。
- *扩散链路*：Prefab 实例 → 独立按钮锁 → 模式切换 → `_transitioning` 拒绝 → `ReturnToStartPanel` → 首次进关中断。

### P1-2 相机拓扑变化缺少画面与输入验证

- *问题*：Main 场景 Camera 失活，同时 Dig Level 1 相机改为 MainCamera 并增加 URP Camera Data；生命周期静态可闭合，但任一持久化绑定、渲染栈或输入相机差异都可能表现为黑屏、叠加、HUD 不可见或触控偏差。
- *影响文件*：`Assets/Game/Scenes/Main.unity`、`Assets/Game/Prefabs/DigLevel/DigLevel_001.prefab`。
- *建议*：在主项目 PlayMode 与 Android/iOS 横屏分别验证首页、进 Level 1、HUD、触控、死亡/重置、胜利/下一关、回首页；保存截图与日志，并确认任一时刻只有预期相机输出。
- *Git 依据*：Main Camera `m_IsActive: 1 → 0`；Dig 相机 `Untagged → MainCamera` 并新增 URP Additional Camera Data。
- *扩散链路*：场景/关卡 Prefab → 持久化相机开关 → URP 渲染 → UI/HUD 与触控射线 → 关卡可玩性。

### P1-3 动态字体清理后缺少 SBP 与移动端首用验证

- *问题*：`en SDF` 删除约 299 个缓存字形和额外 atlas，`Twinkly SDF` 也清空动态表。该动作符合动态字体清理设计，但缺少构建顺序和移动端首次动态回填证据。
- *影响文件*：`Assets/Game/ArtSrc/Font/en SDF.asset`、`Assets/Game/ArtSrc/Font/Twinkly SDF.asset`；受影响范围包括 Loading 与引用这些字体的 UI。
- *建议*：运行项目实际 SBP/资源包构建；在 Android/iOS 冷启动检查 Loading、英文、标点、省略号和目标语言字符，记录首帧/首次打开内存与文字截图。
- *Git 依据*：字体资产当前字符/字形表为空，`en SDF` 的额外 atlas 子资产被移除；两者 Dynamic 与 clear-on-build 标志仍在。
- *扩散链路*：字体资产 → 构建清理/资源包 → TMP 首次请求 → 动态 atlas → 文本显示与运行时峰值。
