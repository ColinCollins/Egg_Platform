## direct conclusions：源码能直接推出的结论

1. **断网前置存在，但覆盖有条件。** 八入口的 NotReachable 分支均在本次业务加锁和请求之前；其它网络状态继续原链路。缺配置、已购、已有 busy 或不可点的按钮可能在到达该分支前返回，不能保证任意点击都有相同提示。
2. **无终态时关闭 WaitingPopup 不等于解除购买锁。** 公共购买没有注册等待关闭回调，Shop/Chest/Coin/NoAds/胜利入口没有从该关闭动作收口锁的代码。条件为有效商品已进入平台请求且请求不返回；这时等待 UI 能关，业务请求仍 pending。
3. **不能将关闭重开视为共同恢复办法。** Shop/NoAds 的正常关闭本身受购买锁阻止；只有外部生命周期真的关闭/重建才谈得上重开。局部面板锁可以在 OnOpen 复位，但 Chest/Coin 锁在长生命周期控制器，重开 Popup 不复位。Chest OnOpen 还会清视觉 ClickBlock，handler 仍因控制器 busy 返回，存在“视觉已恢复但业务仍拒绝”的路径。
4. **晚成功的交付边界已存在差异。** Chest/Coin 控制器保留 offer，并在视图版本检查之前交付；这不等于所有发奖异常已安全。Skin 在 Disable 后 pending 为空，晚成功到达 787 时不进入 GrantSkin，且 success=true 不进失败提示。Shop 若由外部关闭触发 pending 清空，晚回调的 Coin 补发会在 616–619 跳过。是否发生实际订单漏发须平台验证。
5. **服务不可用不必然卡死。** 缺商品对象会走公共 false 回调；平台返回 false 也会让各业务清锁并提示。只有未完成或异常未被映射成业务结果的分支才留在请求状态。不能把所有“有网无服务”都写成必然无回调。
6. **P1-2 的两个影响文件不足以描述根链路。** 还必须包含 PurchaseManager、WaitingPopup、ChestGiftController；其它七类入口/控制器属于逐场景影响验证范围。Skin 晚交付上下文丢失已在原日报 P0-5 单列，不把它作为本次新增问题重复计数。

## hypotheses：需要复现后才能归因

- 有 Wi-Fi/蜂窝但商店/支付服务不可访问时，底层可能不产生终态，继而触发上述锁保留路径；也可能正常返回失败。没有本次平台日志，不能选定其中一种为事实。
- SDK Request 426 等待底层 Purchase，之后才登记 Completer；失败/取消回调若先于登记，或 await 链异常而未转换为 false，可能不能触达业务收尾。PurchaseManager 的外层同步 try/catch 不能证明异步故障会回 false；具体时序、异常类型与平台影响均待复现。Packages 保持只读。
- 同 SKU 重入时 SDK:409–412 会复用 pending Completer；Skin 切页允许重入、局部面板重建和其它入口购买可能使多个业务上下文关联同一平台结果。是否重复计数/误交付须按订单逐项核对，不能仅从这条复用推断已发生重复发奖。

## missing evidence：真机与沙箱验收清单

每个入口都需执行上面的八种场景，Android/iOS 分别记录；另覆盖 Chest 五档、Coin 首购/普通、三类胜利普通/Reward。有效商品、无效配置、已有权益和冷启动无详情应分开建用例。

每条用例记录：设备/OS、构建 commit、沙箱账号、入口/Prefab/商品/SKU、初始余额/皮肤/权益/PurchaseCache、系统 reachability、服务故障方式、操作时间线、按钮 active/Interactable、Waiting/ClickBlock/UI 栈、提示 key、业务锁/pending、SDK 请求与终态、订单标识、最终余额/权益/皮肤/次数及重入次数。无法观测的字段标为未取得，不用推测填值。

1. 正常支付：结果返回、奖励到账、次数、奖励展示、交互恢复分别核对；包含重复结果后的幂等性。
2. 飞行模式/系统明确无网：验证提示、不新建等待、不新加锁、不请求、不发奖；再次点击与关闭仍可操作。
3. 系统显示有网但服务不可达：保留设备连接并用测试网络阻断商店服务；记录是正常失败还是始终没有终态，不能用 NotReachable 用例代替。
4. 缺本地映射、详情不存在、详情存在但价格为空：分别记录可点击状态、提示和请求；不得合并为“无价格”。
5. 平台失败/取消：验证原生覆盖前后状态、提示、所有锁及导航恢复；将平台取消与等待窗手动关闭区别记录。
6. 无终态后等手动关闭按钮显示并关闭等待：立即检查所有业务按钮与遮罩，再尝试再次点击、退出、切页；关闭操作不能充当平台已取消的证据。
7. 若正常退出被锁阻止，先记录“正常关闭不成立”；外部关闭/销毁重开作为另一个独立生命周期用例。Chest/Coin 验控制器 busy；Skin 验 Disable 后 pending；Shop 验 pending Coin。
8. 控制故障恢复后送达晚成功/晚失败：验证旧视图不会误操作新实例、奖励不漏不重、当前等待 UI 不被旧结果误关。涉及再次请求时按订单对照每一次发奖。
