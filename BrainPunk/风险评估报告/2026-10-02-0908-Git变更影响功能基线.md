2. `DigLevelCtrl` 在同一物理批次先比较全部接触病菌；任一不可吞噬则失败。全部病菌被领取且吞噬动画完成后，只有 `TrySucceed()` 能锁定并提交成功。证据：`Assets/Game/Scripts/Level/DigLevel/DigLevelCtrl.cs:84-160`。

### 4. 存档、奖励和回调

1. `DigGameLevelCtrl.RecordVictory()` 先修改内存中的 Passed/Unlock/Current 状态，再调用 `DB.SaveDigGame()`；保存失败只记录日志，不回滚内存。证据：`DigGameLevelCtrl.cs:69-82`。
2. `DigPlayCtrl` 先创建首胜或重复胜利面板，再调用 `RecordVictory()`；面板创建失败不会提前消耗首胜记录。证据：`DigPlayCtrl.cs:170-182`。
3. Dig 分享奖励先由 `SimpleBag.AddTool()` 增加金币并保存 `GameData`，再把关卡写入 `DigGame.SharedLevelIds` 并保存 Dig 存档。若前者成功而后者失败，跨重启可能重新满足分享奖励资格。证据：`GameVictoryPanel_Share.cs:447-470,532-542`、`SimpleBag.cs:110-171`。
4. Dig 首胜激励广告在 `_isRewardAdRequesting=true` 后依赖回调清锁；`RewardAdHelper` 能在 WaitingPopup 关闭时取消“等待广告加载”，但没有证据证明原生展示后永久不回调也能恢复。NoAds IAP 的 `_isNoAdsPurchasing` 同样依赖 `IapManager.Request(...).ContinueWith(...)`，当前链路未见超时。证据：`DigGame_GameVictoryPanel_Reward.cs:217-305`、`RewardAdHelper.cs:38-80`、`DigGame_GameVictoryPanel.cs:234-313`、`PurchaseManager.cs:492-545`。
5. 当前工作区把 Android 解析目标从 FusionAds `1.5.1` 改为 `1.5.2`；Resolver 文件仍保留两个版本的本地仓库文件记录，最终解析结果必须以 Gradle dependency tree/AAB 为准。

### 5. 打点与共享事件

1. `DigPlayCtrl` 类注释和实现明确“不发正式关卡统计”；在 Dig 代码范围搜索不到 `level_start`、`level_end`、`b_play`，只在胜利面板发现 NoAds 的 `IAP_CLK`。因此 Dig 进入、成功、失败、Reset、Replay、时长和跨模式累计不进入现有正式关卡生命周期口径。
