## 变更入口到影响链路

### 1. `PlayCtrl_Success.cs` 为什么会影响主流程和广告收益链

- 改动意图：把 Victory 面板从“统一面板”改成“首次通关奖励版 / 非首次普通版”分流，并把“重复通关不再获取奖励”提前到主状态机入口判断。
- 影响模块：游戏主线核心流程、Victory 界面弹窗、广告奖励、IAP、成就解锁、打点。
- 扩散链路：
  `Level success -> PlayCtrl_Success.OnEnter -> HasPassedCurrentLevelBefore() -> TryToAddSuccessCount() -> RatingPopup -> GameVictoryPanel.Create(levelData, !hasPassedCurrentLevelBefore) -> 奖励版 Victory prefab / 普通版 Victory prefab`
  `PlayCtrl_Success -> GameSDKService.LevelEndEvent -> InterstitialAdHelper.TryToShowInterstitial -> Victory 面板展示顺序`
  `PlayCtrl_Success -> WaitingUnlockAchievement -> GameAchievementUtils`
- 风险扩散原因：这里是通关后的总收口。只要奖励版 Victory 没接完整，影响就会同时落到玩家结算体验、广告发奖、IAP 入口、成就解锁时序和成功打点。

### 2. `GameVictoryPanel.cs` / `HorizontalRandomAdRewardCtrl.cs` 为什么会影响奖励闭环

- 改动意图：新增首通奖励表现，包括倍率摆针、奖励飞行动画、NoAds 入口和新的 reward prefab。
- 影响模块：Victory 奖励弹窗、广告奖励、道具入账、货币打点、UI 动画、远端配置。
- 扩散链路：
  `GameVictoryPanel.Create -> GameVictoryPanel_Reward.prefab -> AdRewardBtn / NoAdBtn / rewardAnimCtrl / HorizontalRandomAdRewardCtrl`
  `HorizontalRandomAdRewardCtrl.RefreshRewards -> ConfigManager.RemoteConfig.GetVictoryHorziontalRewards -> guru_spec.yaml(level_config.victoryHorziontalRewards)`
  `AdReward 正常闭环本应继续走 RewardAdHelper.TryToShowRewardAd -> 回调成功 -> SimpleBag.AddTool -> GameSDKService`
- 风险扩散原因：当前实现已经连上展示层和配置层，但还没有真正连上广告回调与发奖层，属于“主流程已接入，闭环未完成”的高风险状态。

### 3. `HintBubble.cs` / `PlayCtrl_Playing.cs` / `LevelRuntimeState.cs` 为什么会影响提示系统稳定性

- 改动意图：修复 GuideBubble 重复显示，接入 `HintsDisappearTime`，并支持运行时语言切换刷新。
- 影响模块：关卡内提示、状态机、语言切换、关卡配置字段语义。
- 扩散链路：
  `PlayCtrl_Playing.UpdateGuideBubble -> LevelRuntimeState.HasShownGuideBubble -> ShowHintBubbleEvent -> BaseLevelCtrl.OnShowHintBubbleEvent -> HintBubble.Show(desc, disappearTime)`
  `HintBubble.OnEnable -> EventCenter.AddListener<SwitchLanguageEvent> -> RefreshTips(currentTxtId)`
- 风险扩散原因：这条链直接挂在 `PlayCtrl_Playing.Update` 上，且绑定事件订阅和自动关闭；一旦状态重置、事件解绑、配置字段语义不一致，就会表现为重复提示、文案不刷新或提示停留时间错误。

### 4. `guru_spec.yaml` 为什么会把 Victory 风险扩散到远端配置和平台差异

- 改动意图：把 Victory 奖励倍率从本地常量扩展成远端 `level_config.victoryHorziontalRewards`。
- 影响模块：远端配置、Victory 奖励倍率、不同渠道配置差异。
- 扩散链路：
  `guru_spec.yaml(level_config) -> RemoteConfigService / ConfigManager.RemoteConfig -> HorizontalRandomAdRewardCtrl.GetRewardMultiplier() -> rewardTxts`
- 风险扩散原因：倍率文案虽然显示在 UI 上，但配置入口已经放在远端链路。只要 JSON 结构不稳定、远端没下发或平台包拿到旧缓存，展示和值班逻辑就可能不一致。

### 5. `Assets/GF` / 字体资产 / `ProjectSettings.asset` 为什么会影响构建可发布性

- 改动意图：启用 DOTweenPro 的 TMP 支持，调整多个 TMP 字体 atlas，并在多平台 define 中加入 `DEBUG_MODE`。
- 影响模块：TMP 动画、文本渲染、日志开关、调试按钮、设备端调试组件、构建裁剪。
- 扩散链路：
  `Assets/GF/DOTweenPro*.asmdef -> Unity.TextMeshPro 引用 -> Victory / HintBubble 的 DOText 等扩展`
  `TMP Font Asset atlas -> Victory / HintBubble / Loading 等 TMP 组件`
  `ProjectSettings scriptingDefineSymbols -> StartPanel / GameSettingPopup / DebugModeSwitchAllBtns / Booster`
- 风险扩散原因：这是“子模块编译开关 + 字体资源 + 多平台 define”同时变化的组合，不是单点资源问题，而是跨构建与运行时的复合风险。

- *Git 依据*：当前工作区 diff 明确显示 `GameVictoryPanel_Reward.prefab` 的 `rewardTxts` 为 7 个 `{fileID: 0}`，同一工作区里的 `HorizontalRandomAdRewardCtrl.cs` 仍保留旧的短路逻辑。
