## 变更入口到影响链路

### 链路 A：Android 广告二进制到业务回调

```text
mainTemplate.gradle / AndroidResolverDependencies.xml
  -> Gradle 选择 FusionAds 1.5.2
  -> Guru AdsManager / GameAdsController 初始化与观察者
  -> GameAdsManager
  -> GameSDKService.Ads
  -> InterstitialAdHelper / RewardAdHelper
  -> Main / Draw / IWanner / Dig 及其它广告消费者
  -> 展示、失败/取消、奖励、广告计数、原生覆盖后的遮罩与输入恢复
```

影响原因：这两个文件是当前实际 Android 二进制选择入口；即便 C# 包装层未改，SDK 初始化或回调语义变化仍会沿公共包装层扩散到所有消费者。

### 链路 B：首页两个 Dig 入口到转场回退

```text
两个激活 DigGameEnter 实例
  -> 各自 OnEnable / Refresh / enterButton.OnClick += Enter
  -> 第一次 TryEnterDig 激活 Dig，DigPlayCtrl._transitioning = true
  -> StartPanel 在翻页遮满前仍存在，另一按钮拥有独立 0.1 秒门禁
  -> 第二次 TryEnterDig：ControllerManager 因 Dig 已活动而返回成功
  -> DigPlayCtrl.TryEnterCurrentLevel 因 _transitioning 返回失败
  -> GameManager.TryEnterDig 调用 ReturnToStartPanel
  -> Dig Deactivate 增加版本并清理当前转场资源
```

影响原因：Prefab 新增了第二个独立按钮实例，单个 `CustomButton` 的实例内门禁无法约束另一按钮；UI 资源差异因此扩散到控制器状态和转场取消。

### 链路 C：Dig Level 1 / Main 相机到画面与输入

```text
tbdiglevelsort 1 -> 40001
  -> tbdigleveldata 40001 -> DigLevel_001
  -> DigPlayCtrl 关闭 Normal UI、创建 Dig HUD、加载 Prefab
  -> 关闭持久 StartCamera
  -> 实例化带 MainCamera 标签和 URP AdditionalCameraData 的 Dig Camera
  -> DigLevelCtrl.inputCamera 执行屏幕到世界投影
  -> 关卡画面、HUD 最终绘制和挖掘坐标
```

```text
  -> 30 个 Twinkly / 181 个 en 直接引用资源
```

影响原因：两个共享 FontAsset 被大量资源直接引用；源字体存在是缓解证据，但不等于 SBP 产物和移动端冷启动已经验证。
