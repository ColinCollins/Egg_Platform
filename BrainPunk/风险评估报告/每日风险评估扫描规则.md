# 风险评估报告功能设计

更新时间：2026-04-30  
用途：约束后续“风险评估报告”自动化的扫描入口、扩散路径和报告结构。核心变化：**不再按固定模块清单起扫**，改为从最近 Git 变更入口出发做风险扩散。

## 设计结论

后续日报不再以“广告、界面弹窗、游戏主线核心流程、打点数据统计”四个模块作为扫描入口。它们只作为受影响模块的归类标签和兜底知识库，不作为固定扫描顺序。

新的评估必须从变更事实开始：

1. 最近三天 Git commit。
2. 当前工作区未提交变更。
3. 上述变更直接影响到的调用链、回调链、资源链、状态链、打点链。

## 评估范围

每次风险评估必须覆盖：

| 范围 | 必做内容 | 输出要求 |
|---|---|---|
| 最近三天 Git commit | 收集 commit 标题、作者、时间、改动文件、增删状态 | 写入 `最近三天 Git 变更摘要` |
| 当前工作区未提交变更 | 收集 `git status`、`git diff --stat`、`git diff --name-only`，必要时读取具体 diff | 写入 `当前工作区未提交变更` |
| 受影响模块的调用链 | 从直接修改文件出发，追踪调用方、被调用方、事件、资源、配置、DB、SDK、UI、状态机、打点 | 写入 `变更入口到影响链路` |
| P0 哨兵范围 | ClassCollector、link.xml、构建裁剪、核心入口、构建前处理、资源剥离 | 写入独立工程链风险段落 |

固定核心模块的功能基线仍可参考，但只能用于判断“变更影响了哪个模块”和“旧风险是否被触发或修复”，不能替代 Git 变更入口。

## 评估方式

每组变更按以下链路扩散：

```text
直接修改文件
  -> 文件职责 / 改动意图
  -> 受影响模块
  -> 调用方 / 被调用方
  -> 回调 / 事件 / 状态机
  -> 资源 / prefab / ScriptableObject / 配置
  -> 持久化 DB / PlayerPrefs / 远端配置
  -> 打点 / 广告 / IAP / 成就 / 平台 SDK
  -> 失败路径 / 重复触发 / 平台差异 / 性能与内存风险
```

风险条目必须能回答三个问题：

1. **风险从哪个 Git 变更入口来**：commit、未提交 diff、资源或子模块变更。
2. **风险如何扩散到运行时**：玩家路径、系统触发路径、回调链或资源加载链。
3. **为什么是当前优先级**：阻断、收入、数据污染、状态卡死、资源不可见、平台差异等具体影响。

## 必做命令

### 1. 最近三天 commit

```powershell
git log --since='3 days ago' --date=iso --pretty=format:'%h %ad %an %s' --name-status
```

必要时补充：

```powershell
git show --stat <commit>
git show --name-status <commit>
git show -- <path>
```

### 2. 当前未提交变更

```powershell
git status --short
git diff --stat
git diff --name-only
```

对高风险文件必须读取具体 diff：

```powershell
git diff -- <path>
```

### 3. 子模块变更

如果 `git status` 显示子模块 modified，必须进入子模块检查：

```powershell
git -C <submodule-path> status --short
git -C <submodule-path> diff --stat
git -C <submodule-path> log --since='3 days ago' --date=iso --pretty=format:'%h %ad %an %s' --name-status
```

### 4. P0 哨兵

正式日报前必须先执行：

```powershell
powershell -ExecutionPolicy Bypass -File D:\GitStore\BrinPunk\BrainPunk\tools\Check-P0RiskGuard.ps1 -Days 3
```

如果哨兵命中 P0，日报必须保留独立的 P0 工程链风险段落。需要即时提醒时再追加 `-SendFeishu`。

## 变更分组规则

先按 Git 变更事实分组，再映射模块。不要先按模块找风险。

| 变更组 | 典型路径 | 扩散检查 |
|---|---|---|
| 关卡逻辑 / prefab | `Assets/Game/Scripts/Level/LevelItem/*`、`Assets/Game/Prefabs/Level/*` | 关卡入口、胜负条件、提示、交互按钮、玩法面板、资源引用、成就、通关和重开 |
| Loading / 主流程 | `LoadManager`、`EnterLevelLoading`、`PlayCtrl`、`BaseLevelCtrl` | 启动、热更新、资源加载、状态机、Pause/Playing、进入关卡、下一关、失败兜底 |
| 广告 / SDK | `Runtime/Ads`、`SDK/Services/Ads`、`GameSDKService.*` | 初始化、ready、等待弹窗、取消、TimeScale、奖励回调、插屏计数、失败退避 |
| UI / 弹窗 | `Assets/Game/UI/*`、`Bear.UI` | 打开/关闭、遮罩、栈顶限制、按钮可用性、暂停恢复、动画回调、资源加载失败 |
| 打点 / 数据 | `GameSDKService.Game`、`SimpleBag`、`LevelRuntimeState`、DB 字段 | 重复计数、多计数、余额 before/after、关卡进度、买量点、revive、duration |
| 配置 / Luban / RemoteConfig | `Assets/Configs`、`Luban`、`ConfigManager` | 字段兼容、默认值、排序映射、远端缺失、解析失败 |
| 资源 / 字体 / 美术 | `ArtSrc`、`Font`、`.prefab`、`.asset`、Address/Yoo 资源 | 缺资源、错引用、atlas、导入设置、资源包路径、平台差异 |
| 外部依赖 / 子模块 | `Assets/GF`、SDK 子模块 | asmdef 编译、宏开关、第三方 API、业务调用点 |
| 工具 / 飞书 / 自动化 | `tools`、`风险评估报告` | 报告解析、P0/P1 字段格式、忽略规则、发送失败处理 |

## 扩散检查清单

对每个直接变更点，至少检查：

1. **入口触发**：玩家从哪里触发，系统从哪里调用。
2. **调用链**：调用方、被调用方、协程/UniTask、事件订阅和回调。
3. **资源链**：prefab、asset、font、atlas、Address/Yoo/Resources 路径。
4. **状态链**：游戏状态机、Pause/Playing、TimeScale、按钮 interactable、遮罩、UI stack。
5. **数据链**：DB 字段、PlayerPrefs、RemoteConfig、Luban 表、缓存。
6. **打点链**：事件名、字段语义、重复触发、多计数、失败/取消是否上报。
7. **失败路径**：资源缺失、配置为空、网络失败、SDK 未 ready、回调不来、异常抛出。
8. **重复触发**：重复订阅、重复弹窗、重复奖励、重复计数、重复保存。
9. **平台差异**：Editor、Android、iOS、IL2CPP、裁剪、权限、SDK 行为。
10. **验证缺口**：是否需要 Unity 编译、PlayMode、真机广告、截图或日志验证。

## 报告结构

日报必须使用以下结构：

```markdown
# yyyy-MM-dd 风险评估报告

## 最近三天 Git 变更摘要
## 当前工作区未提交变更
## 变更入口到影响链路
## P0 风险
### P0-1 标题
- *问题*：...
- *影响文件*：...
- *Git 依据*：...
- *扩散链路*：...
- *建议*：...

## P1 风险
### P1-1 标题
- *问题*：...
- *影响文件*：...
- *Git 依据*：...
- *扩散链路*：...
- *建议*：...

## 观察项
## 已缓解风险
## 本次未覆盖
```

`Send-AdsRiskReport.ps1` 只强依赖 `问题 / 影响文件 / 建议` 字段；新增的 `Git 依据 / 扩散链路` 必须保留在日报中，用于人工复核。

## 结果回传要求

每次完成日报评估后，除了执行飞书发送，还必须把本次报告信息直接同步给我，作为自动化任务的默认收尾动作。

## 当日风险复核

工作日的日报完成后，另行执行一次当日复核。复核以**当日正式 Git 变更驱动日报**为输入，逐条检查其中的 P0、P1 和观察项；P0 哨兵提醒、功能基线和历史日报只能补充证据，不能替代当日正式日报。若当日正式日报尚未生成，记录缺口并停止本次复核，不得改用昨日文件冒充当日输入。

复核时记录日报生成时间、复核时间、当时的 Git HEAD 与工作区状态，并检查两次之间的提交、未提交 diff、相关代码/Prefab/配置、修复记录及可用的编译、Unity、构建或真机证据。用“原报告编号 + 标题 + 影响路径/触发链路”匹配风险，不仅凭编号相同认定是同一风险。

每条原风险只归入以下一种状态：

| 状态 | 判定依据 |
|---|---|
| 已消除 | 有可定位的修复或回滚证据，且对应触发路径已有足够的验证结果；写明原风险、改动、验证和关闭时间。 |
| 仍存在 | 触发条件、危险代码/资源或原验证缺口仍在；写明最新证据和下一步。 |
| 待验证 | 有修复线索但缺少足够的运行、构建、设备或业务验证，或当前证据相互矛盾；写明所缺证据，不得算作已消除。 |

三天扫描窗口滑过、文件不再 dirty、风险未在新日报出现、仅有修复提交或文档宣称修复，都不足以独立证明风险已消除。若发现日报漏列的新风险，另列“新发现风险”并给出当前证据，不得将其混作原风险状态变化。对已消除项也应写明验证范围，避免把局部修复扩大为整个链路关闭。

复核报告保存为 `yyyy-MM-dd-HHmm-每日风险复核报告.md`，放在本目录，至少包含：对照日报路径与时间、复核时间及 Git 基线、原风险逐条对照、已消除风险、仍存在风险、待验证风险、新发现风险、验证范围与未覆盖、总体结论。各状态段落用 `- 原 P0-1 标题：证据与结论` 形式列出，便于飞书摘要提取；无条目时写 `- 无`。

复核报告落盘后，使用 `Invoke-ReportGitUpload.ps1 -ReportPath <复核报告绝对路径> -GitCommitMessage "每日风险复核报告"` 单独提交并上传本次报告，再使用 `Send-FeishuRiskReview.ps1 -ReportPath <复核报告绝对路径>` 发送包含已消除、仍存在、待验证和新发现风险的复核摘要。Git 上传失败仍继续发送飞书；两步的成功或失败均需回传。不得让发送脚本自动选择目录中“最新 md”，必须传入本次复核报告的绝对路径。

## 收尾顺序

最终日报生成后的任务顺序固定为：

1. 报告 `.md` 落盘到 `D:\GitStore\BrinPunk\BrainPunk\风险评估报告`
2. 触发独立 Git 上传脚本：

```powershell
powershell -ExecutionPolicy Bypass -File D:\GitStore\BrinPunk\BrainPunk\tools\Invoke-ReportGitUpload.ps1 -ReportPath <本次最终风险评估报告绝对路径>
```

3. 如需预演，可先执行：

```powershell
powershell -ExecutionPolicy Bypass -File D:\GitStore\BrinPunk\BrainPunk\tools\Invoke-ReportGitUpload.ps1 -ReportPath <本次最终风险评估报告绝对路径> -DryRun
```

4. Git 上传步骤之后，再执行飞书发送：

```powershell
powershell -ExecutionPolicy Bypass -File D:\GitStore\BrinPunk\BrainPunk\tools\Send-FeishuReport.ps1
```

5. `Send-FeishuReport.ps1` 现在只负责解析最新日报并发送飞书，不再承担 Git 上传职责。
6. 即使 Git 上传失败，也要保留本地报告并继续执行飞书发送；最终回复中同时回传 Git 上传结果和飞书发送结果。

最终回复至少包含：

1. 报告标题。
2. md 文件绝对路径。
3. 整体风险等级。
4. 最高风险。
5. 关键风险点。
6. Git 上传结果；如果失败，补充失败步骤、错误信息和下一步排查建议。
7. 飞书发送结果；如果失败，补充错误码、错误信息和下一步排查建议。

## P0/P1 判定

### P0

- 会阻断启动、进入关卡、重开、通关、下一关。
- 会造成广告奖励、IAP、登录、核心收入路径明显异常。
- 会导致关键 KPI、买量点、关卡进度、虚拟货币余额重复计数或多计数。
- 最近三天 Git 变更直接触达核心入口，且失败路径缺少兜底。
- 构建裁剪、ClassCollector、link.xml、资源剥离导致运行时类型或 prefab 缺失。

### P1

- 造成局部 UI 卡住、按钮不可点、遮罩不退、文本或资源不可见。
- 造成潜在重复请求、重复保存、重复弹窗、性能或内存风险。
- 依赖特定资源、平台、配置、网络或用户操作顺序才触发。
- 新增第三方依赖、asmdef、宏开关或字体/atlas 变更需要 Unity 回归。

### OBS

- 环境性文件、构建时间、低概率缓存低效。
- 暂未发现直接业务影响，但需要人工确认是否应提交。

## 禁止项

- 禁止只按“广告、弹窗、主流程、打点”四个标题泛泛复述旧风险。
- 禁止没有最近三天 commit 或当前工作区 diff 依据就复制旧风险。
- 禁止只看直接修改文件，不追调用链、回调链、资源链、状态链和打点链。
- 禁止忽略子模块、本地未提交改动、资源/配置文件对运行时的影响。
- 禁止把固定模块基线当成扫描入口；它只能作为变更影响判定的参考资料。
