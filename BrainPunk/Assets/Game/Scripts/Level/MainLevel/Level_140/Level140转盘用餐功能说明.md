本关目标是默认输送方向的餐点被顾客真实吃完，玩家通过改变路线拿到餐点；不是用“是否反转”限制玩家进食。玩家到自己的位置落稳后自动锁定，不再有坐下按钮；逐个快速吃同盘、允许跨盘累计三份，原地变大完成后等待0.5秒通关，不再显示“好吃！！！”气泡。机器开局直接满条，每次有效点击出一盘一至三份，随后加载 2.2 秒并保持满条等下一次点击；数量使用接餐预测。顾客累计三份膨胀换人，同盘反转或绕回再次经过仍可取食。第八次出餐后故障，剩余食物仍可通关，食物耗尽不判负、不自动重开。四席幕罩仅为视觉效果。默认方向无漏餐及玩家实际三份通关均待人工验收，不能把静态预测当作运行证明。

当前依据为用户2026-09-20确认与源码/Prefab。本轮编译、局部隔离运行及渲染证据见上节；后文旧验证记录只描述当时范围，主工程及移动设备仍未验收。

## 主流程

### 入场与 Reset

1. 不执行共享 StartDoor 演出；保留标准玩家对象、物理、阴影与成功系统，FallArea/陷阱等正常失败继续沿共享流程自动重开。
2. 从当前 Alien 的 `DrawEntrancePathView` 缓存起点和最终摆放，并在 Awake 按共享 `ResetCount/FailCount` 判定是否重开；仅首次入场把 Alien 搬到场外起点。夹持阶段保留玩家人工挂接的局部姿态，第一帧停止其刚体模拟并隐藏整个 Shadow（包括动态子阴影）。
3. Alien 沿原起终点移动，`clip_close` 切换为 `clip_open`，玩家脱离夹子，根节点恢复正向单位缩放，再开启 Dynamic 物理自然下落。Shadow 恢复共享跟踪逻辑，Alien 沿原路退场。
4. 玩家落稳且 Alien 退场完成后开放操作，机器直接进入绿色满条待点击状态，不执行开局加载。
5. 手动 Reset 或正常失败后的重开均不播放运输：本关 Start 主动调用 `Actor.EnsureInitialized()`，随后立即执行 `RestoreRetryState()`，即使共享状态仍是 PAUSE 也不延后。先冻结物理，在原松爪点脱离夹子，按正向 Polygon 脚底几何向下找非 Trigger Ground 并同步写入 Transform/Rigidbody 站立位置，设定不透明 idle、恢复 Shadow，再隐藏 Alien。该初态准备完毕后才按当前游戏状态决定是否恢复物理；失败次数由共享失败重开流程处理。
6. 无落点、引用缺失或首次松爪超过 8 秒未落稳时记录错误并停止本关，不伪造已落地或成功。

共享 Reset 创建关卡后发出黑幕渐退事件，再保持 PAUSE 约 1 秒；当前 `GamePlayPanel_000` 继承的黑幕渐退时长为 0.2 秒。不能把 Actor 重开定位放在受 PLAYING 门禁限制的 Update 中，否则会出现画面已显露、玩家仍在场外的窗口。本关将视觉初态准备和物理/输入恢复分开：Start 期间完成前者，PLAYING 恢复后才做后者，不延长黑幕、不改共享暂停。`EnsureInitialized()` 的一次性门禁防止 Unity 随后调用 Actor.Start 时再次隐藏 Shadow 或冻结已经恢复的角色；首次 Alien 送入流程不改。

### 自动入座、连续逐份进食与原地通关

- 玩家席仍是最左侧；自动入座保留水平sitReach=0.2、接地和竖直速度小于0.35的规则，锁定idle等待，普通等待可以Jump离位。玩家与顾客的原席位高度不变。
- 首份仍按餐盘前后帧X扫过玩家席位领取，不以转向限制进食。领取后锁操作，当前份入嘴且1.5倍速eat结束，立即从当前盘领取下一份；只有一份飞嘴在途，当前盘不被其他顾客抢取。输送带和盘子照常运动。
- 同盘吃空且总数不足3份时EndEating回锁定idle，恢复机关／起身操作并保留累计食量。跨盘也可以累计；累计达到3份即停止领取，不拿第4份。
- 三份实际入嘴、零在途且最后eat完成后播放expand和原膨胀音效，继续使用本实例台面裁切。expand结束切expand_idle，主角保持原地、席位／输入／物理锁定，等待0.5秒后通过原SuccessStrightly结算一次。没有玩家滚动退场、出屏门禁或镜头跟随关闭；顾客仍保留膨胀滚走。
- 计时由本关PLAYING时钟推进，暂停冻结，StopRuntime后无迟到结算；常规死亡／失败重开沿既有共享链。玩家仍不弹“好吃！！！”气泡，不新增语言词条。

### 顾客等待消息气泡

- 顾客连续处于 Seated 等待满 **3 秒**才有资格说话；进食、膨胀、退场和补位途中不累计等待，重新坐好后重新计时。只在入场结束且本关 PLAYING 时推进出场等待/显示/冷却时间，暂停不累计，Reset 新实例清零。
- 从有资格的顾客中等概率选一位，随机选一句，文案不连续重复；同时最多一个顾客气泡，关闭动画期间也占用该名额。保留 `CustomerBubbleDisplaySeconds = 1.5 秒`，到时请求共享收起；等关闭动画完成并销毁后，再随机冷却 **5～8 秒**才选下一位，不使用共享默认 20 秒或旧的 2.5 秒。
- 说话顾客一旦领取食物就请求收起气泡，不阻塞正常进食；玩家领取第一份起收起当前顾客气泡，本次尝试不再生成新顾客气泡，玩家自己不弹气泡；已有气泡沿共享关闭动画结束，不强制截断共享表现。
- 表现复用原 `Resources/HintBubble` Prefab 和 `HintBubble.Show(key, customer.Root, 0f)`；传 0 关闭共享自动倒计时，本关计满 1.5 秒或进食/退出中断时调用共享 `CloseStraightly()`。不新增气泡脚本、布局、字体、Animator 或文字动画，不修改共享组件；关闭动画和销毁仍由共享组件处理。退出/Reset 时随 runtimeRoot 清理，资源缺失仅警告一次，不影响玩法。
- 顾客气泡实例在 Show 前先设根缩放为零，与共享 show 动画首帧一致；后续缩放与文字效果由共享组件驱动，不另做弹出动画。
- `customerWaitingBubbleKeys` 在 Prefab 显式绑定以下四个 key，CSV/I2 同步登记，仅 zh-CN 有值，其余 75 个语言槽留空：

|---|---|

| `S_LevelTips_Des_level_140_3` | 全部都是我的！ |

### 机器与食物

状态为：入场（显示满条）→ 满条待点击 → 点击出餐 → 加载 2.2 秒 → 满条待点击；第八次出餐改为直接进入故障，胜负后进入终态。没有等清盘或补位完成后再开始读条的状态。

- `Sp_l140_jd_01.png` 是中间透明的外框（已核对 PNG alpha）；`jd_02` 为初始/待点击/本盘处理中的绿色常驻态；`jd_03` 为红色加载条。三张原图都是 151×31、100 PPU、中心 pivot，红绿条自身已包含透明留边，因此额外内缩 `progressFrameInset` 为 0，不再二次缩小。层级顺序为机器本体 < 进度 < 外框；进度是外框子节点，满条时按原图尺寸居中对齐并绘制在框下，保留外框描边。加载、待点击和故障满条共用该尺寸。
- 每次进入/Reset 后直接显示绿色满条；入场结束后可直接点击出第一盘。前七次有效出餐后立即开始 **2.2 秒**红条加载，完成后切回绿色满条并保持，只有玩家随后新一次点击机器才吐下一盘。加载期间按下不排队，也不能一直按住等加载完成后放手来出餐。
- 单盘七种食物均匀随机选一种，同盘各层都是该种。按 `sw1` 的三层 Y 偏移生成所需数量，所有层 X 居中于盘子；盘子最低层，上层食物 sortingOrder 高于下层。生成的整盘以盘子中心统一放大为模板的 **1.2 倍**，盘子、食物及层间距同步放大；不缩放手摆模板根节点，不改变左右落点或飞行轨迹，取食脱父级时保留放大后的世界尺寸再逐渐缩小。
- 盘子及食物从机器顶部作抛物线飞向落点；落点在点击时固定，中途反转不改抛物线终点。默认投左侧 `sw1`，反转后投右侧 `sw1 (1)`。
- 每次有效出餐生成餐盘、开始抛出时播放一次共享 `throwItem`，包括第八盘；加载中或故障后的无效点击不播放。转盘反转和持续运转不额外播放音效；进食按本轮规则在实际入嘴时播放eat。
- 整盘运行对象保留世界姿态后挂到 `zt`，继承转台外层排序组 `202`，组内排序取台体/带面最大 Order +1。因此 `Sp_l140_jq_02` 独立根级 `201` < 整盘 < 其余机器组 `203`，盘子/食物不以独立根级排序盖住机器。取走后飞嘴的单份食物仍脱离餐盘、按原根级 `205` 绘制。关卡禁用时单独销毁挂在转台下的餐盘，不销毁手摆转台或带面。
- Actor 保留共享 Prefab 原有 `SceneLayer / 200`，本关不覆盖其排序；所有初始和补位顾客共用 CreateCustomer，根排序统一为 `SceneLayer / 199`。脱离 Alien 后的排序为顾客 `199` < 玩家 `200` < `jq_02 / 201` < 转台及餐盘外层 `202` < 其余机器 `203`；顾客膨胀和退场保留该排序，各组内部顺序和物体位置不变。
- 2.2 秒计时结束后，即使上一盘仍在飞行/转动、顾客正在进食/退场/补位，也允许有效点击出新盘。只有出餐重置读条；食物吃完与 Alien 补位完成不刷新进度，也不自动吐食物。多盘分别记录自己的飞行、食物层数及取食资格；当前 2.2 秒不保证每盘完全吃完才出下一盘。玩家一、两份的 eat 完成回待机后可继续出餐；第三份领取后进入最终演出收口，不再接受新出餐，既有转盘/食物/顾客继续运行至玩家原地变大并完成半秒成功等待。

### 转盘与空盘

- `zt` 中 `Sp_l140_zm_02_*` 横向循环移动，`zm_01` 台体、椅子与机器不移动。第一次有效出餐点击启动向左输送，之后读条、满条待点击、顾客补位和机器故障期间仍持续移动。
- 从转盘上开始的一次按住拖动，向右净世界 X 位移达到 **3** 后永久改为向右输送；不足距离松开清零，不累计多次手势。
- 保持当前手摆的 22 片带面。带食物的盘子在相机外循环回到另一侧：反转时从右侧落点出屏，再从左端进入，先遇到玩家。屏外回绕不参与座位扫过判定，不瞬移到玩家面前。
- 空盘继续随当前转向移动，盘子包围盒完全离开相机可见范围才销毁；空盘不回绕。
- 座位首次命中继续使用前后帧X扫过、从最上层取一份。顾客保持原规则，同盘反转或绕回仍可接餐；主角领取后按本轮规则串行连吃当前盘，进食中另一盘经过不并行领取。未入座／满额／膨胀或补位空席不接餐，与方向无关。

### 顾客、接餐预测与三份膨胀

三个席位仍按屏幕从左到右记录，默认实际取食顺序是右、中、左。NPC 使用 Box Skeleton，不复制玩家输入、皮肤绑定或失败组件。出餐不再使用 `RecipeCount/Portions` 八行表：

1. 点击时采样三个顾客的已吃份数、飞嘴在途份数、当前阶段及阶段剩余时间；吃满后的可再次接餐时机包含 eat、expand、Alien 进场和松爪/退场，并预留 0.15 秒预测余量。旧顾客膨胀完成后的滚动出屏与补客并行，不再计入席位恢复等待。
2. 将全部现存餐盘剩余食物、当前位置和飞行剩余时间加入预测，不再因曾喂过某位顾客而排除该盘下一次到站的接餐机会。已经飞向嘴部的食物计入占用，不再重复当作空余容量。
3. 从本盘三、二、一份依次尝试；同时将余下至第八次的订单按最快 2.2 秒间隔、每次至少一份加入预测。用到站事件顺序推进顾客计数和补位，选取能覆盖当前与后续最低供餐需求的最大数量，避免只顾眼前这一盘。
4. 默认方向上已经错过的席位不借下一圈当成成功接餐；反向行程按实际回绕距离计算。预测仅安排数量，不替玩家或顾客吃掉食物，实际取食仍由真实经过座位触发。
5. 若预测没有覆盖方案，仍出一份且本次只警告一次，不返回零、不等待补位、不屏蔽玩家进食。该警告代表需要人工核对参数/反向旧盘的预测缺口，不代表已保证所有时序不漏餐。

每位顾客累计吃满三份后才膨胀，不要求来自不同餐盘。取食开始登记 `PendingBites`，抵达面部才增加实际 Count 并释放在途占用；只有实际 Count 达三、所有飞嘴食物抵达且 eat 动画完成，才执行 `expand → expand_idle`。新顾客的已吃和在途计数清零。

确认实际 Count 达三、无飞嘴在途且 eat 完成后先播放膨胀；膨胀完成、开始滚动离开座位的同帧立即派 Alien 送新 Box，不提前到膨胀开始，也不等旧顾客出屏。旧顾客由独立退场列表继续以 **100°/秒顺时针自转**、2.5 世界单位/秒向右离场，出屏后才销毁；不因补客提前消失。转盘仍为 2.4 世界单位/秒。Alien 送新 Box 到同一抬高锁定点，退场后计数/在途清零并恢复接餐，不改变机器读条或满条状态。旧顾客和新顾客都在本关运行时根下，统一暂停与卸载清理。

### 食物入嘴表现

- 移除 `Actor 根位置 + (0.25,0.65)` 的固定目标。当前 Box 没有独立 mouth 命名骨骼，使用吃饭动画会移动的 `Black` 面部骨骼作为跟随基准。

- 顾客各自创建指向自己 Skeleton 的跟随器，并复制同一个子点标定，不共享玩家的运行时骨骼引用或重建事件订阅。
- 食物飞行改为 0.3 秒，放在 LateUpdate 读取当前面部挂点；前 60% 行程保持原大小，末段平滑缩小，抵达目标后才移除并计数。角色移动、镜像和面部动画不再依赖一个固定世界偏移。
- 默认嘴部偏移属于静态标定，实际对嘴精度仍需用户人工观察；可以直接调整 `FoodMouthPoint`，不能把源码跟随正确扩大为视觉已验收。

### 膨胀音效

- 玩家和顾客进食均不播放额外音效。
- 顾客或吃满三份的玩家开始 `expand` 时播放一次 `expandSfxTag`，当前复用已注册的 `spring`；`expand_idle` 和滚动退场不重复触发。
- 膨胀 tag 在本关控制器 Inspector 可替换，留空关闭音效；通过共享 `Game.Scripts.Common.AudioManager.PlaySound` 非循环播放，遵循全局音效开关和默认音量 0.4。不修改共享声音集合、原音频或进食规则；暂停期间不产生新的本关音效，已播放的一次性声音沿共享音频生命周期处理。实际音色、叠音和时机尚未试听验证。

### 旋转时的台面遮挡

- 保持当前等待点、离地高度和自转速度，不通过抬高角色改变轨迹。
- 顾客或玩家进入 `expand` 时才启用该实例的裁切材质；台面界线取手摆 `zm_02` 带面 Sprite 的世界 `bounds.max.y`。
- Shader 按世界 Y 丢弃低于台面上沿的像素，不依赖台体图片向下覆盖的有限高度，也不整只隐藏 Box。普通等待/进食中的玩家和顾客、补位中的新顾客不使用该材质。
- 复制的是该角色自己的材质，通过 Spine `CustomMaterialOverride` 接入，保留 straight-alpha/PMA 输入方式；共享 Box 材质不改。顾客副本随顾客销毁回收，玩家副本在本关禁用/卸载时清理，不污染共享 Actor 或其它关卡。

### 故障、烟雾与手动重开

第八次有效点击正常生成第八盘后立即进入 Broken，禁止继续出餐，但视觉用 **0.4 秒 SmoothStep** 过渡：本实例 `jq_03` 从原透明度渐隐，结束后才禁用 Renderer；满条由绿色逐渐过渡为红色，不瞬间换色。红条完整绘制在底层，临时绿条覆盖在上层渐隐，结束后销毁绿条；进度根使用独立的嵌套 SortingGroup，整体仍位于机器本体与外框之间，不改变外框、机器或食物的相对排序。转盘和现存食物照常运行，仍允许反转、坐下和切换幕罩；即使没有剩余食物，也不判负、不触发重开，保持现场直到玩家自己按 Reset。

过渡开始 **0.15 秒**后启动烟雾并播放一次共享 `passwordError`，与第八盘的 `throwItem` 错开；烟团继续使用已有的短暂淡入，并随机向左上或右上消散，不循环重播故障提示音，不调用 `failed` 或改变结算。过渡沿本关玩法时钟推进，暂停时冻结；Reset/卸载时临时绿条随进度节点清理，停止玩法后不会迟到触发音效。两种提示音均沿共享音效开关、默认音量与一次性播放生命周期处理，实际过渡和混音未运行验证。

烟雾以 Prefab 中用户手摆的 **`Sp_l140_hy_01` SpriteRenderer** 为唯一出生姿态模板，`smokeTemplate` 显式引用它。每团生成时读取模板的世界位置、旋转、尺寸及 Sprite/材质/颜色/翻转；不再固定到机器顶部，也不再叠加右下尾端偏移。新烟团按本轮随机方向绕原喷口旋转后喷出，分别缓存出生位置和速度；后续移动模板只影响新烟团。

模板在编辑器中保留可见；进入运行时只关闭模板自身 Renderer，避免静态预览与烟团叠加，视图清理时恢复原启用状态，不修改或销毁模板。每隔 0.3 秒接续一团，每团持续 1.2 秒，短暂淡入后逐渐消散；固定五团循环复用，不做正弦往返或呼吸缩放。故障长期停留也不持续累积实例。

正常坠落/死亡不属于“食物耗尽不判负”的例外。`Level140BaseLevelCtrl` 继承共享 `IsFail()`，`CheckFinished()` 对成功、共享失败标记或 Actor 死亡提交一次结果。FallArea 沿 `OnTriggerFailArea → WaitingFail` 播放失败音效，等待 0.2 秒后设置失败，再经 `TryToRestart` 等待 1 秒发送 Failed Reset；不额外调用 Actor.Die 或新增重开计时。陷阱/Actor 死亡也恢复共享结算入口。本关收到失败区域信号后停止玩法，随后由共享重开接续，不再永久停住等待手动 Reset；其它关卡代码不改。

### 墙面开关与四席聚光幕罩

- 开局/Reset 没有幕罩，保持当前场景原貌。墙面开关由 `Level_140.prefab` 根下**手摆的两个常驻节点**组成（底座 `Sp_l146_kg_01` + 单个蓝色拨杆 `Sp_l146_kg_04`），编辑器未进入 Play 时即可见、可直接拖动/缩放；运行脚本不改写 Sprite。`lightSwitchRenderer` 显式绑定底座，`lightSwitchLever` 显式绑定该唯一拨杆。OFF 取编辑器手摆姿态：底座 (4.802097,3.076255) + 拨杆 (4.802097,3.77) 旋转 0°、缩放 1，X 已对齐，排序底座 0 < 拨杆 1（SceneLayer）；ON 取用户摆好的翻转后位置 `lightSwitchOnLocalPosition=(4.802097,2.5,0)` + 叠加 `lightSwitchOnAngle=180°`。
- 两态表现不再换图，而是**位置+旋转一起切**：`Configure` 缓存拨杆编辑器的 `localRotation/localPosition` 作为 OFF，`Show` 切到 ON 位置+朝向，`Hide` 与 `OnDestroy` 回到 OFF。不改缩放、Sprite，不做过渡动画；命中区并入两 pose 的拨杆包围盒，上下两端都可点。
- 开关命中区取底座与拨杆的合并包围盒（`Encapsulate`），拨杆转开后仍能点中整只开关；点击优先于机器/转盘，与 `Serve` 互斥。
- 开启时背景压暗、四个上窄下宽的聚光区域出现；关闭恢复原貌。光束从相机上沿延伸至台面，幕罩覆盖相机世界画面；HUD 不属于此世界幕罩，墙面按钮排序高于幕罩，保持可见可点。
- 黑色幕罩目标透明度读取游戏已有 `UIManager.MaskAlpha`，开/关时长读取 `MaskFadeDuration`；当前 `Assets/Game/Scenes/Loading.unity` 配置为 **0.8 / 0.2 秒**，不再使用独立的 0.48 / 0.3 秒。无已有 UIManager 时使用其类默认值 0.5 / 0.2 秒，不访问会自动创建单例的 Instance。四束光的形状和内部白色微亮 0.08 保持不变。
- 显隐按 `UIMask.Show/Hide`：开启从零线性淡入，关闭从当前透明度线性淡出，非正时长立即完成；关闭途中重开按共享 Show 规则从零开始。使用 `Time.unscaledDeltaTime` 独立推进，暂停仅停止玩法，不冻结幕罩过渡或改变开关状态。
- 对齐共享 UI 遮罩的创建/隐藏边界：首次开灯才创建幕罩 Mesh/Material，淡出结束后停用幕罩子节点，后续复用，不把“关灯”当作销毁。成功、失败、Reset 等 StopRuntime 请求淡出；关卡禁用/卸载时立即随 runtimeRoot 销毁，并释放自建 Mesh/Material、把拨杆放回编辑器 OFF 姿态与位置，不把对象搬到持久根等待淡出。

- 这是纯视觉层，没有真实灯光或风扇功能，不改变出餐加载、顾客进食、接餐预测、转向或成功条件。开关点击与机器点击、转盘拖动互斥，不会同时出餐。
