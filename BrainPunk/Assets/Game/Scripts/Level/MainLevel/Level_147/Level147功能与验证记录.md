## 实现与调参

- 场景中预放的对象均通过 SerializeField 显式绑定。HUD 创建后通过当前 `PlayCtrl.LevelCtrl` 获取本关控制器，无全局状态交接或按节点名搜索。
- 角色基类在 Start 初始化刚体；本关等待两个刚体就绪后启动。专用动作使用 Kinematic/零重力，但玩家碰撞体保留，供原星星 Trigger 使用；下车归还原刚体类型、重力和控制。
- 角色在车上的位置由各车 `seatOffset` 控制。`soloSpeed` 是玩家不上车时的慢速；`raceSpeed`、`catchUpSpeed`、`acceleration` 控制比赛节奏。追赶与领先差距连续改变，不瞬移两车。
- 轮转使用实际每帧位移：`角度 = -位移 / 轮胎半径`，不是另开恒速动画。`wheelTurnsPerPedalCycle` 表示传动比，蹬踏速率随真实车速变化；倒退只改变位移和轮子转向，不倒放角色动画。
- 骑行时从前到后为主角 SortingGroup=220、黄车父级=215、黑盒子=210、红车父级=185；主角到终点停车后改为212，置于黄车后、黑盒子和红车前，下车走动保持。子轮/车架的排序只控制同一车内部，必须同时检查父级组，不能只改 SpriteRenderer。
- 道具命中按场景相机投影到屏幕；UI 拖动按指针的 pressEventCamera 或当前内层 Canvas 相机换算。超过 EventSystem 拖动阈值后抑制本次点击，松手周期结束才恢复；次指针不能接管当前拖动。
- 门落点沿用场景终点区域的摆放；延长赛道时与终点红线、EndPoint 一同右移。`doorDropHeight`、`doorDropDuration` 可调下落距离和速度。落门后出口 Trigger 仅在破解成功并下车后启用；门飞走不会发送失败事件。
- 仅在本实例仍是当前关卡、PLAYING、未转场/死亡/进门时推进动作。暂停冻结比赛、上下车与结束序列，并取消未完成拖拽；重开销毁重建，箭头、开场与胜负状态均重新初始化。
