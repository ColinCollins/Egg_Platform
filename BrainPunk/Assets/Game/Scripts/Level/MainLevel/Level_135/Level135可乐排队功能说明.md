## 数据、输入和资源流

主控启动校验绑定、初始化原三瓶及8名顾客。顾客服饰通过原Actor内的已绑定 BoneFollower挂点实例化，保持原父级缩放和前后关系；NPC模板关闭玩家控制与皮肤存档组件。排队及插队受罚以138为参考，只在135本地实现差异。

服饰层级修正依据 `ActorSkinBinding.ApplyPartAsync` 与 `Actor.prefab`：衣服挂点本来是Default层、排序2，Spine分段为1/5；翅膀原Sprite为Default层、排序0。135先前额外给背饰加SceneLayer的SortingGroup，即使order=-1也会整体盖过Default层的身体和衣服。现移除该额外组，衣服/饰物按主角绑定方式归零局部位置与旋转、使用单位缩放，保留原挂点和各部件内部排序。没有改共享Actor、SkinBinding或服饰资源。

固定感叹号使用135独立气泡Prefab：由主控显式绑定并实例化 `Level135ColaAlert`，`ShowQuestion` 直接设置 `tmpTxt.text = "?"`，1.5秒后主控调用 `ShowExclamation` 改成 `"!!!"`，全部字符同时可见，再保留0.8秒。气泡不带共享HintBubble，也保留对嵌套Tips中Localize组件的移除；无翻译查询和语言事件订阅。喷发开始时销毁该气泡，旧关清理兜底销毁。点单与插队提示仍用原多语言HintBubble。

`BaseRaycaster` 命中可操作瓶后捕获一个指针。起手尊重现有 GraphicRaycaster 的 UI 遮挡；拖动越过瓶子边界后保持该指针，其他指针的抬起不能释放它。松手、暂停、失焦和组件关闭会释放归位。售卖从当前游标按左中右循环，跳过正在拖动、归位或渐显的瓶；售出后从实际售出瓶的后一槽继续，全部暂不可用时才等待且不推进游标。这替换了初版“拿住轮到的瓶就停止服务”的规则及原方法注释。

实际售卖时把原 SpriteRenderer 交给接收者的 `CupBinding`，捕获该瓶有气状态；库存新建普通瓶，原位渐显。原瓶先挂关卡根执行飞行，到手再挂 `Box_Center9s` 右手骨骼。喷发开始时原瓶留在起喷处、瓶口朝左，接收者由浪头带走；此原瓶始终由接收者绑定负责回收。

浪花前端 `FrontX = 起喷X - 总喷射长度 × 进度`。水柱长度、末端泡沫位置和角色推动使用同一进度，角色右侧边缘未碰到浪头时不移动，碰到后随浪头向左。聚拢顾客用少量前后错位保留造型可辨识性。已离场顾客的碰撞盒关闭后 `bounds` 为空，因此提前缓存其身体边缘，避免漏推。

喷发阶段为 `Question → Alert → Blast → Fade → Idle`。浪头抵达离屏终点后才开始Fade，瓶子、水柱及浪花使用同一透明度；淡出前不销毁原瓶，淡出结束才取消服务、回收顾客。主角失败分支也在完整推进和渐隐后交给原 `Die()` 流程，避免原失败清理提前删除喷发瓶子。感叹号气泡关闭由本关时钟负责，取消共享气泡的独立自动倒计时。

美术仅引用 `Assets/Game/ArtSrc/Sprites/l135` 的普通/有气瓶、水柱、泡沫和瓶盖素材，不改原图片。喷水部件无独立物理碰撞，主控统一处理清场，避免推动玩家或店员。
