## 当前行为与调用链

### Draw

1. 普通选关：`DrawGame_ChoiceLevelPanel.TryEnterSelectedLevel()` → `GameManager.TryEnterDrawLevel()` → `DrawPlayCtrl.TryEnterLevel()` → 加载关卡 → 擦除过场完成。
2. OneLink：`OneLinkLevelRouter.TryEnterDraw()` → `TryEnterOneLinkLevel()` → 同一选关／进关链。
3. 对于过场后播放 Intro 的关卡，先等 `PlayVisibleIntroAndBeginDrawingAsync()` 完成；两种 Intro 路径最终进入 `CompleteIntroAndBeginDrawing()`。
4. 在现有 `BeginDrawing()` 和进关标志解除之后检查 `HasDrawGameGuidePopup`；false 时创建 Popup，成功后立即保存 true，并调用 Draw 的 `Pause()` 和既有 `GamePlayPanelSwitchBlockEvent(true)`。同一同步调用中完成暂停，不新增延时或协程。
5. 确认后销毁弹窗，回调只允许原激活版本、原运行时实例、Drawing 阶段且非加载／Reset 过渡中的关卡恢复；解除 HUD 点击锁，再检查原免广告弹窗资格。

### IWanner

1. 首组、选组、指定小关和 TBN 请求都进入 `OpenCurrentLevelAsync()`，保持原解锁、续关、资源、进度与统计口径。
2. 关卡／HUD 创建成功、必要广告等待结束、黑幕淡入完成、原小关统计开始后，在现有加载完成点检查 `HasIWannerGameGuidePopup`。
3. false 时创建 Popup，成功后保存独立 true，并使用当前控制器的 `Pause()`：禁用 HUD 输入并暂停关卡，角色移动输入按原暂停接口归零。
4. 确认后只允许原激活版本、原实例且非加载／组结算状态调用 `Resume()`；角色／HUD 输入按原恢复接口恢复，然后检查免广告弹窗资格。

### 共用边界

- “首次进入”指实际关卡完成加载／Intro，单纯打开 Draw 选关或 IWanner 选组不消耗记录；不限制必须进入第一关，新旧用户都按各自记录判断。
- `HasDrawGameGuidePopup` / `HasIWannerGameGuidePopup` 默认 false，互不影响，不使用主线 `HasBegineTutorial`。`GameData.Init()` 将两者重置为 false；正常返回、重进、切关、Reset 不重置记录。
- 弹窗的 `Create(Action onClosed = null)` 仅在 `Application.isPlaying` 时访问 UI／DB。暂停与恢复由控制器负责，不在 `OnShow()` 中切换主线状态。
- UIManager 同步执行 `OnCreate` → `OnOpen` → `OnShow`。确认按钮已通过 Prefab 序列化引用绑定；缺按钮时销毁不可关闭弹窗并返回 null，资源加载失败也返回 null，两种失败均不写 Has 记录、不暂停玩法。
- 展示成功即记为已展示，与 BeginerPopup 的记录时机一致，不等待用户确认。保存返回 false 时记录 Bear warning，当前会话仍为 true；跨重启的一次性保证依赖实际存档写入成功。
- 点击后禁用确认按钮，`OnClose()` 在调用回调前清空委托；重复关闭或 `OnDestroyView()` 不重复恢复玩法。临时被其它 Popup 隐藏只执行 `OnHide()`，不消费关闭回调，仍保持玩法暂停。
- 原免广告弹窗不会同时覆盖首次 GuidePopup；资格检查延后到有效关闭回调，不提前消费相关标记。GuidePopup 创建失败／已展示时继续原检查。
- 关卡清理先断开／置空旧运行时，再销毁持有的 GuidePopup；玩法退出还会先提升激活版本。清理回调不恢复其它关卡、不弹出免广告窗口。
- 不新增全局事件；复用现有 HUD Block 事件。未修改 RemoteConfig、Loading、SDK、广告请求、支付、关卡脚本、统计开始／结束公式、Packages、GuruSDK 或 GF。引导时长沿原暂停边界不累计控制器游玩时间。

## 存档依据

## 2026-10-13 覆盖安装历史通关门禁

### 修改前核对记录

- 需求与验收对象：覆盖安装后的旧存档若对应玩法已经存在通关记录，则 Draw / IWanner 首次操作引导不再弹出；无通关记录的新档仍按原规则各展示一次。必须保留正常进关、弹窗创建成功后的暂停／恢复、免广告弹窗顺序、关卡结算和统计行为。
- 行为基线：两个入口当前只检查 `GameData.HasDrawGameGuidePopup` / `HasIWannerGameGuidePopup`。旧 JSON 缺少这两个 2026-10-09 新增字段时会保留默认 `false`，因此历史玩家即使已有玩法通关数据，覆盖安装后首次进入对应玩法仍会弹出。
- 权威来源与维护边界：Draw 通关由 `DrawPlayCtrl.RecordVictoryProgress()` 写入 `DB.DrawGame.PassedLevels`；IWanner 完整 Group 通关由 `IWannerPlayCtrl.RecordGroupVictoryProgress()` 写入 `DB.IWannerGame.PassedLevels`。两个列表均由各自玩法存档维护，不修改 `GameData` 生成字段、Popup、Prefab、配置、资源、统计、广告或平台 SDK。
- 拟修改位置与理由：只在 `DrawPlayCtrl.TryShowGameGuidePopup()` 和 `IWannerPlayCtrl.TryShowGameGuidePopup()` 的既有展示门禁中增加“对应 `PassedLevels` 非空则跳过”，使旧档可从已有通关事实直接判定，无需新增迁移字段或覆盖安装检测。
- 影响范围：门禁跳过后沿调用点既有 `if (!TryShowGameGuidePopup()) TryToShowNoAdPopup()` 继续执行，不会暂停玩法或创建／销毁引导 UI；新档空列表、已经记录引导展示、资源失败及关闭回调路径保持原职责。
- 验证计划：静态核对两个通关写入点和两个展示调用点；覆盖 `Has=false + PassedLevels 非空`、`Has=false + PassedLevels 空/null`、`Has=true` 三类组合；执行 C# 编译、定向静态扫描与 `git diff --check`。Unity PlayMode、覆盖安装和 Android/iOS 真机结果在取得实测前标记为 `uncertain`。
- 未决项：IWanner 的 `PassedLevels` 当前语义是完整 Group 通关，不代表只完成 Group 内某个普通小关；本次按现有持久化“已通关关卡”权威口径处理，不扩展到统计字典或断点字段。
